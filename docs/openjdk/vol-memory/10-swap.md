## 现在真正该问的，不再是“该不该换出匿名页”，而是“这页一旦离开内存，下一次访问时系统凭什么还能把它找回来”

上一篇我们已经把回收决策层讲清楚了。你知道系统如何用 LRU 或 MGLRU 识别候选页，如何让 `kswapd` 在后台提前追水位，如何在后台来不及的时候让 direct reclaim 把当前分配者拖进现场，也知道文件页和匿名页的退场代价并不对称。

到这里，回收器已经做出了一个很不情愿但有时必须做的决定：**这张匿名页暂时不值得继续占着宝贵的 RAM，先把它挪出去。**

可“挪出去”这三个字并不是一句结束语。文件页退场时，后面还有文件这个天然后备；匿名页却没有一个普通文件对象替它记住内容。它里面可能是 Java 堆的一部分、某个进程的栈数据、用户缓冲区或匿名共享区。你可以暂时不让它留在内存里，但绝不能把内容忘掉。

这就产生了本篇真正的核心困惑：

- 匿名页要被换出时，数据到底放到哪里？
- 页表原来记录的是“这页对应哪个物理帧”，页离开内存后，PTE 还怎么表达它的去向？
- 多个进程可能共享同一匿名页，swap 位置怎样管理引用？
- 下一次访问这个地址时，内核怎么知道这是普通缺页，还是“这页在 swap 仓库里”？
- 如果换出的页在设备上散得到处都是，换入岂不是每次都要随机读，性能会不会直接崩掉？

所以本篇要建立的顿悟是：**swap 不是简单把页写到磁盘，而是给匿名页安排了一套外部仓库；页表在 Present 失效后不再承载物理帧号，而是暂时承载“仓库类型 + 仓库槽位”的回家坐标。**

先把总图记住：

```text
换出：
  回收器选中匿名页
  分配 swap slot
  把页内容写入 swap
  PTE 从“内存物理页坐标”改成“swap 仓库坐标”

换入：
  访问触发 #PF
  内核发现 PTE 是 swap entry
  先查 Swap Cache
  命中就免 IO，不命中才读设备
  读回后重新建立普通页映射

性能治理：
  slot 尽量按 cluster 组织
  换入时对邻近 slot 做预读
  回收时用 folio batch 分摊锁和 TLB 成本
```

这一篇最重要的一句话是：**匿名页换出不是把页删除，而是把内容搬到仓库，并把仓库坐标藏进 Present=0 的 PTE 里，等下一次缺页时按坐标把它取回来。**

## 一、如果匿名页被回收后只是简单清掉 PTE，系统就会得到一片再也找不回内容的“空地址”

### 1. 最朴素的错误方案：页要腾地方，那就清掉映射，物理页释放，未来访问再重新分配一张

从“先把内存腾出来”的角度看，这个办法很诱人。回收器发现匿名页不活跃，于是清掉所有指向它的 PTE，释放物理页；以后进程再次访问，重新分配一个新页即可。

这样确实能省 RAM，却把最重要的东西丢了：匿名页的内容。匿名页不是一张可以随时从文件重新读出的缓存副本，它的每个字节可能都是进程运行中独自产生的状态。你把物理页释放掉以后，未来重新分配一张“空页”只能得到一块新的内存，不能得到原来那份数据。

所以匿名页的退场不能是“清掉就忘”，而必须是“搬到某个外部后备，再把回家线索留下”。

### 2. 第二个失败方案：把 swap 位置只记在某个全局表里，PTE 清空后再慢慢全局猜

如果意识到要保存位置，下一步也许会想：那就让 swap 管理器在全局维护一张“哪些匿名页去了哪个 slot”的大表；PTE 只要清掉，未来访问时再根据别的关系去查。

这又把地址空间与后备位置之间最关键的联系拆散了。缺页发生时，内核手里最直接的信息就是当前进程、当前虚拟地址和对应 PTE。如果 PTE 自己没有留下“我不是空白，我是去了 swap 的某个位置”这条线索，内核就得依赖额外的全局关系拼图，还要处理多个进程共享映射、PTE 生命周期和 slot 引用变化。

这会让一个本来应该在页表层直接分派的判断，退化成复杂的全局追踪。

### 3. Linux 的答案：PTE 失去 Present 后，剩余位不必浪费，可以改编码成 swap entry

Linux 选择的是非常漂亮的复用：**当 PTE 的 Present 位为 0 时，硬件不会把它当成一个有效的普通页映射去使用，于是内核可以利用剩余位编码 swap entry。**

换句话说，同一条 PTE 在两个时刻可以承担两种不同角色：

- 页还在内存时，它记录物理页帧号以及访问权限。
- 页被换出后，它不再记录当前物理帧号，而记录 swap 的类型和槽位。

硬件看到 Present=0，只会触发缺页；内核拿到这条 PTE 后，则会进一步检查“它是普通空映射，还是带有 swap 坐标的特殊非 Present 映射”。这让地址空间自己就携带了匿名页的回家线索。

### 4. 这个设计为什么值得称为“复用 PTE”，而不是普通编码技巧

因为它把两个原本很难同时满足的需求放进了同一个表项：在内存时需要快速翻译到物理页，离开内存时需要保留后备位置。系统没有为 swap 另建一张和进程页表平行的地址表，而是利用 PTE 的状态空间完成了角色切换。

这使得缺页处理可以沿着当前进程的地址空间直接分派：看 PTE Present 位，若普通映射不存在但 PTE 带有 swap 语义，就知道这不是“从来没分配过”，而是“曾经有内容，只是现在在外部仓库”。

所以 swap entry 的真正价值，不是能塞进几个位，而是**让物理内存世界与外部仓库世界在同一条地址空间门牌上完成接力。** 若要把这一节补成更硬的源码正文，最关键的证据位应回到 `mm/memory.c` 中处理非 Present PTE 与缺页分流的路径，以及 `mm/swapfile.c` 中 swap entry/type/offset 对应仓库槽位管理的实现。它们共同支撑“这不是额外全局表在猜去向，而是当前地址空间的 PTE 自己携带了回仓库坐标”这句判断。

## 二、换出路径：匿名页如何从 LRU 里的候选对象，变成一个带仓库坐标的 swap entry

### 1. 回收器选中匿名页之后，第一件事不是立即写盘，而是先给它找一个可管理的仓库槽位

上一篇的回收决策只回答了“这页值得换出”。真正执行换出时，系统还需要给它安排一个具体位置。这个位置不能只是“某个 swap 设备上差不多哪儿”，而必须成为一个可编码、可引用、可释放、未来能被精确找回的 slot。

因此换出路径首先要向 swap 管理器申请一个可用槽位。这个 slot 的身份通常可以抽象成两部分：它属于哪个 swap 后备来源，以及在这个来源里的哪个位置。前者是 type，后者是 offset。

### 2. 为什么一个 slot 还需要引用计数语义

匿名页并不总是只有一个映射者。`fork`、共享匿名映射、COW 尚未分叉等场景都可能让多个 PTE 暂时共同代表同一份内容。于是一个 swap slot 不能简单理解成“一页对应一格，写完就忘”。系统还要知道：到底还有多少 PTE 或缓存关系在引用这格仓库空间。

这就是 `swap_map` 一类结构存在的意义。它让 slot 有自己的使用计数和状态，区分空闲、仍被映射引用、暂时被 Swap Cache 持有等不同阶段。证据位上，这层最适合回落到 `mm/swapfile.c` 一组围绕 slot 分配、引用计数和回收状态的路径去看：那里说明 swap 后备不是一块傻磁盘，而是一套真的在维护生命周期与引用关系的外部页仓库。

换句话说，swap 不是一个只会顺序写入的文件，而是一套带引用生命周期的外部页存储管理器。

### 3. 把页内容写进 swap 之后，PTE 为什么必须在正确时机切换成 swap entry

换出真正危险的地方在于，内存页内容、设备上的副本、进程页表这三者必须最终收敛到同一套语义。

系统不能在物理页还没有安全写入 swap 时，就先把所有 PTE 改成“去 swap 找”；否则一旦设备写失败，进程地址空间就已经丢掉了唯一可用内容线索。反过来，也不能只写设备却长期保留普通 Present PTE，让 CPU 继续把已经准备释放的物理页当作有效映射。

所以换出是一个带顺序约束的交接过程：先准备并写入后备，再解除原有物理映射，最后让 PTE 以 swap entry 形式留下仓库坐标。具体内部时序会随实现路径变化，但核心不变：**PTE 只有在后备内容已经有了可依赖的位置之后，才应代表“这页已离开内存”。**

### 4. 为什么换出后的 PTE 仍然不是“普通无效 PTE”

从硬件角度看，换出后的 PTE 确实是 Present=0，CPU 再访问时会触发缺页。但从内核角度看，它和“从来没有建立过映射的空 PTE”完全不同。

普通空 PTE 表示：这块地址可能还没兑现，或者需要按 VMA 的匿名/文件语义重新建立；swap PTE 则表示：这块地址过去有一份真实内容，现在内容已被搬到外部仓库，PTE 里有准确坐标。

这就是为什么 `is_swap_pte()` 一类检查非常关键。它把“真正的空缺页”和“暂时在 swap 的页”分成两种完全不同的后续剧本。

### 5. 本节最该记住的结论：换出不是释放页，而是完成“物理页 → swap slot → PTE 坐标”的三方交接

所以如果只记一句话，就记这句：**匿名页换出时，系统先给内容找仓库位置，再把内容写进去，最后把 PTE 改成仓库坐标；物理页可以离开，但地址空间不能失去找回它的线索。**

## 三、换入路径：一次普通内存访问如何识别“这不是新缺页，而是该从 swap 仓库取货”

### 1. #PF 到来时，内核首先要区分两类完全不同的“页不在内存”

当进程再次访问被换出的地址，硬件只看到 Present=0，于是触发缺页。可内核不能只根据这一点就决定“分配一张新页”。因为 Present=0 可能有很多含义：VMA 建好了但匿名页尚未第一次写入、文件页还没加载、栈正在尝试扩展，或者这页早已被换出。

因此换入路径的第一问是：**当前 PTE 是普通空缺页，还是一个编码了 swap 坐标的 swap PTE。** 只有识别出后者，系统才会进入 `do_swap_page` 这条专门的取货路径。

### 2. Swap Cache 为什么存在：换出设备和内存访问之间需要一个临时中转站

很多人第一次听 Swap Cache，会觉得既然页已经在 swap 设备上，为什么还要再搞一个 cache，直接读盘不就好了。

问题在于换出、换入和共享访问可能并发发生。某页刚被写到 swap，物理页或其缓存副本还可能暂时留在内存；另一个进程随后访问同一份内容，也可能已经有人开始把它从 swap 读回来。如果每个访问者都各自重新发起一次设备 IO，就会重复读同一份数据，还会让多个线程围绕同一 slot 互相竞速。

Swap Cache 的意义，就是把“正在 swap 语义下被暂存、读回或共享”的 folio 挂到 swap address_space 的索引里。它是设备和页表之间的临时共享货架。若要补关键源码锚点，这一节最值得回到 `mm/swap_state.c` 中 Swap Cache 索引、命中与生命周期相关路径，以及 `mm/page_io.c`/`mm/memory.c` 中围绕换入时如何接住这份现货的交接逻辑去看。它们共同支撑“Swap Cache 不是设备镜像，而是并发换入/换出的中转与共享货架”这句核心判断。

### 3. 命中 Swap Cache 时，为什么可以免掉一次设备 IO

如果内核根据 swap entry 在 Swap Cache 中找到了对应 folio，说明这份内容已经在内存里，或者至少已经被某个并发路径读回并暂存好了。此时当前访问者没必要再去设备读一遍，只需要等待或复用现成的 folio，再建立自己的 PTE 映射。

这就是 Swap Cache 命中的价值：它把多个地址空间访问同一 swap 内容的情况，收敛到同一份内存中转对象上，避免重复 IO。

从用户体感看，这可能把一次本来要承受设备延迟的换入，降成一次页表映射和引用关系调整。

### 4. 未命中时，`do_swap_page` 如何沿 swap entry 把内容读回来

如果 Swap Cache 没有现成 folio，系统才需要真正从设备取货。它会根据 entry 找到对应 swap 后备与 slot，分配能够承接内容的物理页/folio，把它加入 swap cache，然后发起读取 IO。设备读完成后，IO 完成路径会把 folio 标记为可用，并唤醒等待这份内容的缺页处理者。

接下来，系统建立普通用户页表映射，让当前虚拟地址重新指向这张已恢复的物理页，同时调整 swap slot 引用关系。此后从当前进程视角看，这页又回到了普通可访问内存世界。

这里一定要注意，换入不是“从设备读完就忘了 swap”。在过渡阶段，swap cache、slot 引用和用户 PTE 之间仍有生命周期关系，只有所有必要引用都收敛，才会把临时 swap cache 关系完整拆掉。

### 5. 为什么换入还要预读周围 swap slot

如果每次换入都严格只读当前一个 slot，随机工作集会把设备访问打得非常碎。特别是在某些具有局部顺序性的访问里，当前页取回后，附近几页很快也会被用到。既然一次设备访问和 IO 调度已经付出了固定成本，顺手把邻近 slot 带回来往往更划算。

于是 swap 换入也会引入类似 readahead 的思路：根据当前 slot 选择一个邻近范围，提前把周围内容读进 swap cache。猜对了，后续访问免掉设备等待；猜错了，就多占内存和带宽。

这说明 swap 并不是完全放弃缓存与预测，而是继续沿用“批量、预读、把随机尽量变得更顺序”的性能哲学。

### 6. 本节最该记住的结论：换入的关键不是“读一页回来”，而是先识别 swap PTE，再利用 Swap Cache 和预读把设备取货成本尽量摊薄

所以请把换入路径记成一句人话：**PTE 先告诉内核这页在仓库，Swap Cache 先看门口有没有现货；没有现货才去设备取，并尽量顺手带回附近货物。**

## 四、swap cluster：如果换出时把页随机撒满设备，换入就会把每次访问都变成昂贵的随机取货

### 1. 失败方案：哪个 swap slot 空着就用哪个，先把页存进去再说

从资源管理角度看，最简单的 slot 分配策略当然是哪里空就写哪里。这样寻找空闲位置也许很直接，设备空间利用率看上去也不错。

但它忽略了换入的访问代价。匿名页未来可能按某种局部顺序重新访问；如果它们在换出时被随机散落到设备各处，那么换入就很难形成连续 IO 或有效预读。机械盘上这会带来明显寻道压力，即使 SSD 没有机械寻道，碎片化 IO 也可能增加请求管理与并行调度成本。

换句话说，换出不是只考虑“今天写进去方便不方便”，还必须为“明天可能怎么读回来”留布局。

### 2. Linux 的思路：按 cluster 管理一批连续 slot，让写出布局为未来读回创造局部性

所以 swap 管理会尝试把 slot 按 cluster 组织。你不必把某个 cluster 的确切槽位数量当成永久常量，更重要的是理解它的布局目标：**尽量让一批相邻的 swap 位置保持连续或接近连续，换出时成组分配，换入时才有机会按范围预读。**

这和文件系统、页缓存、readahead 的思路是同一条线：存储布局不是中性的，写入时怎么摆，会决定读取时能不能少做随机访问。

### 3. 为什么 cluster 不是“保证所有页都永远连续”

现实的 swap 设备会被持续分配和释放，多个工作集的生命周期也不一致，因此系统不可能保证每一批匿名页永远完美连续。cluster 更像一种尽量改善布局、降低碎片的策略，而不是绝对承诺。

当理想连续空间不存在时，系统仍要能够从其他空闲区域分配 slot，不能为了保持布局纯洁而拒绝所有换出。于是 cluster 与 fallback、优先级、设备扫描策略之间必然存在权衡。

### 4. swap priority 为什么也属于“取货路径设计”

机器可能启用多个 swap 后备来源，它们的速度、容量、介质类型和管理员意图可能不同。于是系统还需要考虑 swap priority：优先使用哪个来源，何时轮询其他来源，如何在多设备之间分散压力。

这提醒你，swap 并不是一块抽象的“磁盘空间”，而是一个可能由多个后端组成的存储资源池。slot 布局、设备选择和未来换入代价必须一起看。

### 5. `swapoff` 为什么反而需要把所有页找回来

如果一个 swap 后备要被关闭，系统不能只把设备标记成不可用，然后把仍在里面的页留着。那些 PTE 里的 swap entry 还指向它，未来访问就会找不到数据。

所以 `swapoff` 必须沿着全系统地址空间和页表，把仍然使用该 swap 来源的页逐步换回内存，修改对应 PTE，直到所有相关 slot 都脱离，才能真正关闭设备。这是一个非常典型的反向依赖清理过程：外部仓库要消失，所有地址空间里的“回仓库门牌”必须先被收回。

### 6. 本节最该记住的结论：cluster 与 swap priority 共同回答“内容放在哪里，未来怎样更有机会以较低代价取回来”

因此，swap 的 slot 分配不只是内存管理问题，也是一种 IO 布局问题。**换出时尽量让内容形成局部连续，换入时才有机会把随机取货变成范围取货。**

## 五、Folio batch：一次回收成百上千页时，真正该批量的不是“数据”，而是锁、链表和跨核收尾动作

### 1. 失败方案：每回收一页，就单独拿锁、单独改链、单独 flush、单独提交 IO

如果你把单页逻辑逐字面翻译成批量回收，最直接的实现就是循环调用单页路径：每页隔离、每页修改 LRU、每页处理 swap、每页提交或安排 IO、每页做 TLB 收尾。

这在逻辑上容易理解，却会把大量固定成本重复支付。一次回收可能涉及数十页、数百页甚至更多，如果每一页都重新争同一把锁、重新进入相同的管理路径，系统会把大量时间耗在“准备做事”而不是“真正搬数据”上。

### 2. Linux 的批处理思路：先把一批 folio 拿在手里，再集中处理共同阶段

所以回收路径会使用 folio list 等批量容器，把一批候选 folio 一起隔离、处理和释放。这样做的价值不只是减少函数调用次数，更重要的是让多个页可以共享一些管理动作：

- LRU 锁不必每页都重新抢。
- PCP 回灌可以批量完成。
- swap cache 与 slot 处理可以形成更连续的工作段。
- TLB 失效和页表修改可以积累后统一收尾。
- IO 提交更有机会形成设备侧的批量请求。

这就是“批量回收”的真正含义：不是简单把循环写快一点，而是把跨页重复的固定成本摊到一整批 folio 上。

### 3. 为什么批量大小不应被理解成一个永恒数字

某些实现和资料会提到特定的 cluster 或 batch 大小，但你不应该把它们理解成系统永远不变的物理定律。批量太小，锁与调度开销摊不够；批量太大，又可能增加延迟、占用临时内存、让某次回收停顿过长，甚至把不该一起处理的页强行绑在一起。

所以 batch size 的本质是一个工程平衡：在减少固定成本和控制单次工作量之间找合适区间。不同内核版本、设备与回收上下文可能会采用不同边界。

### 4. 本节最该记住的结论：batch 是回收路径反复出现的共同语言，目标是让锁、IO、TLB 和链表操作都不要按页数线性放大

因此请把 folio batch 和前面 PCP、MMU gather、readahead 放在同一张图里看：它们都在做同一件事——**只要固定开销比较重，就尽量按批次摊平，而不是按单页重复支付。**

## 六、把本篇收成一张图：swap 是一条“出库、留坐标、按坐标入库、再用布局和批量压低代价”的完整闭环

现在可以把这一篇彻底收回来。

一开始我们要解决的问题是：匿名页被回收后，数据放在哪里，未来如何找回。答案首先排除了“清掉 PTE，未来重新分配空页”的错误世界。匿名页没有普通文件后备，内容不能凭空再生，所以系统必须把它搬到 swap 仓库，并留下精确坐标。

换出路径先分配 slot、记录引用关系、把内容写入后备，再把 PTE 从普通物理页映射切换成 swap entry。于是 Present=0 不再代表简单空缺，而代表“这页暂时在仓库，坐标已经写在表项里”。

换入时，缺页路径读取 PTE，识别 swap 语义，先看 Swap Cache 是否已有现货。命中就免掉设备 IO；未命中才分配 folio、读设备、完成 IO，再重新建立普通用户页映射。周围 slot 的预读又把可能的随机取货尽量组织成范围取货。

为了让这件事长期不至于被设备随机 IO 拖死，slot 分配还要考虑 cluster 与 swap priority：换出时尽量形成局部连续，换入时才有更高概率批量读取。回收执行本身则通过 folio batch 把锁、链表、IO 与 TLB 收尾的固定成本摊薄。

把这一切压成最短总图，就是：

```text
出库：
  匿名页 → swap slot → 写入外部后备

留坐标：
  普通 PTE → Present=0 的 swap entry
  type + offset 记录仓库位置

入库：
  访问触发 #PF
  识别 swap PTE
  Swap Cache 命中则免 IO
  未命中才读设备并重建映射

布局与加速：
  cluster 让 slot 尽量形成局部连续
  swapin_readahead 减少随机取货
  folio batch 分摊锁与 TLB 固定成本
```

所以本篇最该记住的一句话是：**swap 的优雅不在于它把页“放到了磁盘”，而在于它让 PTE 在页离开内存后仍保留一张可解释的仓库门牌，再用 Swap Cache、cluster、预读和批量操作把这条昂贵的退场与回归路径尽量变得可承受。**

## 七、几个最容易说错的地方

### swap 是不是把匿名页“永久写进磁盘”，之后就只在磁盘里活着？

不是。swap 是一种外部后备与内存压力机制，页可能在内存、swap cache、swap 设备和用户 PTE 之间经历多个状态，是否仍保留内存副本取决于具体路径。

### Present=0 的 PTE 是不是就代表“这页从来不存在”？

不是。普通空缺页和带 swap entry 的非 Present PTE 语义不同，后者包含未来找回匿名页的坐标。

### swap entry 是不是另一张独立页表？

不是。它是编码在特定非 Present PTE 里的后备位置描述，让缺页处理可以从当前地址空间直接识别 swap 语义。

### Swap Cache 是不是简单复制了 swap 设备上的所有内容？

不是。它更像换出/换入过程中的内存中转和共享缓存，命中时可以避免重复设备 IO。

### cluster 是不是保证所有换出页都严格连续？

不是。它是改善 slot 布局、降低碎片和帮助预读的策略，现实压力下仍可能发生回退与分散。

### swap 只适合机械硬盘，SSD 上就没有意义？

不能这样绝对化。后端介质会改变随机 IO 的代价模型，但 swap 仍可能参与内存压力、工作集管理和系统稳定性，具体收益与代价取决于负载和设备。

## 收束：看懂 swap 之后，你才会真正明白“匿名页被回收”不是数据消失，而是地址空间和外部仓库之间完成了一次可逆交接

回到开头那个问题：匿名页一旦离开内存，下一次访问时系统凭什么还能把它找回来？现在答案已经完整闭环了。页被换出前，系统为它分配了有引用生命周期的 swap slot，把内容写进外部后备；随后 PTE 放弃 Present 物理帧语义，改为记录 type 和 offset 组成的仓库坐标。未来访问再次触发 #PF 时，内核就能从这张门牌识别出“这不是普通空页，而是该去 swap 取货”。

而真正让这条路径不至于完全不可用的，又是 Swap Cache、swapin_readahead、cluster 和 folio batch：前者避免并发访问重复 IO，中间两者尽量把随机取货组织成范围取货，后者让回收过程别把锁、链表和 TLB 固定成本按单页放大。

这就是为什么说：**swap 不是“内存满了就把页扔磁盘”的粗暴逃生通道，而是一套把匿名页临时搬离、记录坐标、按需取回，并持续和 IO 随机性、并发性、批量成本做斗争的完整闭环。**

## 八、误解清单、证据清单与边界清单

### 误解清单

- swap 不是“把页永久写进磁盘”这么粗；页会在内存、swap cache、swap 设备和用户 PTE 之间流转。
- non-present PTE 不自动等于“从来没分配过”；它也可能是携带 swap entry 的回仓库门牌。
- swap entry 不是另一张平行页表；它是复用在当前地址空间 PTE 里的后备位置编码。
- Swap Cache 不是把整个 swap 设备镜像进内存；它更像换入换出路径里的中转与共享货架。
- cluster/readahead 不是保证严格连续与必然命中；它们是在随机 IO 现实里尽量改善局部性的策略。

### 证据清单

- PTE 门牌与缺页分流：`mm/memory.c` 中非 Present PTE 与缺页处理相关路径，支撑“PTE 仍然携带 swap 回家坐标”的判断。
- slot 与引用生命周期：`mm/swapfile.c` 中 slot 分配、`swap_map`、type/offset 和引用计数相关路径，支撑外部仓库不是傻磁盘而是有生命周期的页后备管理器。
- Swap Cache：`mm/swap_state.c` 中 swap cache 索引、命中与生命周期路径，支撑“命中时可免设备 IO”的中转站语义。
- 设备交接：`mm/page_io.c` 与相关换入换出路径，支撑页内容写入外部后备、读回并重新建立映射的交接流程。
- 预读与批量：swapin readahead、cluster 与 folio batch 相关路径，支撑“为什么这条昂贵路径还要尽量组织成范围与批次”的性能治理判断。

### 边界清单

- 本文讨论的是 Linux 常见 swap 心智模型；entry 位域、slot 分配、cluster 大小、预读范围和设备策略会随内核版本与架构变化。
- swap 参与的是匿名页外部后备，不等于所有内存压力都该靠 swap 解决；文件页、脏页与 cgroup 边界会改变实际效果。
- SSD、NVMe、zram、机械盘会显著改变随机 IO 代价，但不会改变“匿名页需要外部后备和门牌坐标”这一核心语义。
- Swap Cache、readahead 与 batch 的价值高度依赖访问局部性和并发模式，不能抽象成“开了就一定快”。
- 关闭 swap (`swapoff`) 不是简单卸载设备，而是要求所有仍指向该仓库的地址空间先把门牌和内容收回来。
