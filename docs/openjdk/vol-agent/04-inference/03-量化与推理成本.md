LLM 推理的核心瓶颈是两个：

1. **显存**：模型太大，放不进 GPU
2. **带宽**：把参数从 HBM 读到计算单元需要时间

量化同时解决这两个问题。

3. 量化为什么会产生精度损失？
4. 量化模型为什么还能保持不错的性能？

## 三、直觉方案为什么不够好

### 直觉方案 1：用更小的模型

> 模型太大，那换一个小的模型不就行了？

问题：
- 小模型能力差
- 在某些任务上，大模型量化后仍然胜过小模型
- 不是每次都有"更小的模型"可选

### 直觉方案 2：只保留最重要的参数

> 模型里很多参数不重要，直接去掉。

问题：
- 你不知道哪些参数"不重要"
- 直接去掉参数会破坏模型结构
- 量化保留了所有参数，只是用更少的 bit 表示

## 四、正式机制

### 1. 为什么需要量化

LLM 推理时，主要的瓶颈是"把参数从 HBM 读到计算单元"。

- FP32 的参数：4 字节
- FP16 的参数：2 字节
- INT8 的参数：1 字节
- INT4 的参数：0.5 字节

参数占用的 bit 越少，：
- 模型占用的显存越小
- 从 HBM 读取参数的速度越快
- 计算的吞吐越高

### 2. 量化的基本思想

量化 = 把连续的浮点数映射到离散的整数。

```text
FP32 数值范围：[-3.4e38, 3.4e38]
INT8 数值范围：[-128, 127]

量化就是把 FP32 范围"压缩"到 INT8 范围。
```

关键：**量化不是剪枝，而是压缩。**

### 3. 对称量化 vs 非对称量化

#### 对称量化
```text
FP32 值 × 缩放因子 = INT8 值
INT8 值 × 缩放因子 = FP32 值（近似）
```

缩放因子由最大绝对值决定。

#### 非对称量化
```text
FP32 值 = (INT8 值 - 零点偏移) × 缩放因子
```

- 零点偏移允许非对称分布
- 常用于激活值（通常不是对称的）

### 4. 不同类型的量化

#### FP16（半精度）
- 16 位浮点
- 范围有限，但精度保留好
- 大多数模型可以直接用 FP16 推理，几乎无损

#### INT8（8 位整数）
- 8 位整数
- 范围有限，需要小心处理
- 精度损失较小，但显存节省一半

#### INT4（4 位整数）
- 4 位整数
- 范围更小，精度损失更大
- 需要特殊数据类型（如 NF4）

### 5. 量化为什么能保持性能

模型参数有一个特点：

> 参数的分布通常是"近似正态"的：大部分参数集中在 0 附近，少量大值。

量化的缩放因子由最大值决定，所以：
- 大部分参数用 INT8 表示时的精度损失很小
- 少量大值被"截断"或"重新映射"
- 总体精度损失可控

### 6. 训练后量化 vs 量化感知训练

#### 训练后量化（PTQ）
- 模型训练完成后，直接量化
- 简单、快速
- 精度损失稍大

#### 量化感知训练（QAT）
- 训练过程中模拟量化效果
- 模型学会了"适应量化"
- 精度损失更小

## 五、最小实现 / 伪代码

### 1. 对称量化

```python
import numpy as np

def symmetric_quantize(weights, num_bits=8):
    # 计算缩放因子
    max_val = np.max(np.abs(weights))
    q_max = 2 ** (num_bits - 1) - 1    # INT8 最大值 127
    scale = max_val / q_max

    # 量化
    q_weights = np.round(weights / scale).astype(np.int8)
    return q_weights, scale

def symmetric_dequantize(q_weights, scale):
    return q_weights.astype(np.float32) * scale

# 测试
fp32_weights = np.random.randn(64, 64) * 0.1
q_weights, scale = symmetric_quantize(fp32_weights, 8)
deq_weights = symmetric_dequantize(q_weights, scale)

# 计算误差
error = np.mean((fp32_weights - deq_weights) ** 2)
print(f"FP32 显存: {fp32_weights.nbytes / 1024:.1f} KB")
print(f"INT8 显存: {q_weights.nbytes / 1024:.1f} KB")
print(f"量化误差 (MSE): {error:.6f}")
```

### 2. 显存节省对比

```python
model_params = 7e9  # 7B 模型
for bits in [32, 16, 8, 4]:
    mem_gb = model_params * bits / 8 / 1e9
    print(f"{bits}-bit: {mem_gb:.1f} GB")
```

## 六、复杂度与边界

1. **量化不是免费的——精度会损失**
   - 大多数任务上，INT8 量化损失可忽略
   - INT4 量化在某些任务上会有明显退化
   - 需要针对具体任务验证

2. **量化的收益随 bit 数递减**
   - FP16 → INT8：节省 50% 显存，几乎无损
   - INT8 → INT4：再节省 50%，但精度损失更大

3. **不同层对量化的敏感度不同**
   - 注意力层比 FFN 层更敏感
   - 越重要的层，越需要高精度

4. **量化不是万能的**
   - 不能解决所有计算瓶颈
   - 计算强度（compute-bound vs memory-bound）决定量化收益的大小

## 七、论文与真实系统映射

- **GPTQ**（Frantar et al. 2023）：基于 Hessian 矩阵的量化方法
- **AWQ**（Lin et al. 2023）：激活值感知的量化
- **QLoRA**（Dettmers et al. 2023）：4-bit 量化 + LoRA

在真实系统里：
- 几乎所有 LLM 部署都使用量化（FP16 或 INT8）
- 量化是部署大模型到消费级 GPU 的关键技术
- 量化后的模型还可以配合 KV Cache 量化进一步降低显存

## 一句话结论

> **量化用更少的 bit 表示模型参数，降低显存和带宽需求。FP16 几乎无损，INT8 损失可控，INT4 需要特殊处理。它在大多数任务上能保持模型性能，同时大幅降低推理成本。**
