## 三、直觉方案为什么不够好

### 直觉方案 1：预训练就是让模型背下所有数据

> 把海量文本喂给模型，让它记住。

如果只是"记住"，那模型在测试集上应该很差（过拟合），但实际不是：

- 预训练模型确实在训练数据上表现好
- 但在没见过的数据上也能泛化
- 说明它不是在"背"，而是学会了语言规律

### 直觉方案 2：数据越多越好，不管质量

> 只要数据量够大，模型就能学会一切。

问题：
- 重复数据降低训练效率
- 低质量数据（垃圾、错误、有害内容）会污染模型
- 数据配比不合理会导致某些能力缺失

所以预训练不是"数据越多越好"，而是"数据越干净、越多样越好"。

## 四、正式机制

### 1. 预训练目标：Causal Language Modeling

预训练的核心任务非常简单：

> 给定前文 token，预测下一个 token。

损失函数就是交叉熵。对每个 token 位置计算交叉熵，然后取平均。

这就是"预测下一个词"的数学定义。

### 2. 预训练数据

#### 数据来源
- 网页爬取（Common Crawl、网页存档）
- 书籍、论文、代码仓库
- 社交媒体、论坛

#### 数据清洗
- 去重：去除完全相同的文档
- 过滤：去除低质量、有害、垃圾内容
- 质量分类：用分类器对文档打分

#### 数据配比
- 不同来源的数据按比例混合
- 常见：80% 网页 + 10% 书籍 + 5% 代码 + 5% 学术（配比因模型设计而异，此处仅为示意）
- 配比直接影响模型能力倾向

### 3. Scaling Laws：参数、数据、计算的三者关系

Scaling Laws 的核心发现（Kaplan et al. 2020）：

> 模型性能（困惑度）与参数量、数据量和计算量之间的关系，服从幂律。

也就是说：
- 模型越大，性能越好
- 数据越多，性能越好
- 计算量越大，性能越好

但三者不是独立的。关键结论：

#### 如果只增加参数量，不增加数据量
- 模型很快过拟合
- 参数增长收益递减

#### 如果只增加数据量，不增加参数量
- 模型容量不够
- 数据增长收益也递减

#### 最优分配
- 参数量和训练 token 数应当按比例增长
- 更大的模型需要更多的训练数据

### 4. Chinchilla 的修正

Hoffmann et al. 2022 的 Chinchilla 论文进一步指出：

> 大多数模型实际训练得"太少"了——在相同计算预算下，应该用更小的模型、更多的数据。

举例：
- GPT-3（175B）训练了 300B token
- Chinchilla 认为：在相同计算量下，用 70B 参数、1.4T token 效果更好

这对实践的影响：
- 大模型训练时，数据量和参数量的比例需要精心设计
- 不是"模型越大越好"，而是"数据/参数/计算三者平衡"

### 5. 权重与 Checkpoint

训练过程中，每隔一段时间（通常是几千步）保存一次模型的全部参数。

这些保存的文件叫 **checkpoint**。

每个 checkpoint 包含：
- 所有层的权重矩阵
- 优化器状态（Adam 的动量等）
- 当前训练步数

最终训练完成后，checkpoint 变成"模型权重文件"（如 `.pth`、`.safetensors`），这就是我们通常说的"模型"。

## 五、最小实现 / 伪代码

### 1. 模拟预训练损失曲线

```python
import numpy as np

# 模拟不同模型规模在训练过程中的 loss 下降
# 假设：大模型收敛更快，最终 loss 更低

model_sizes = {
    "small  (100M)":  {"final_loss": 3.2, "steps": 50000},
    "medium (500M)":  {"final_loss": 2.8, "steps": 80000},
    "large  (1B)":    {"final_loss": 2.5, "steps": 120000},
}

for name, cfg in model_sizes.items():
    # 模拟训练 loss 从 5.0 下降到最终值
    steps = np.linspace(0, 1, cfg["steps"])
    loss = 5.0 - (5.0 - cfg["final_loss"]) * (1 - np.exp(-steps * 5))
    print(f"{name}: 最终 loss = {loss[-1]:.2f}, 第 {cfg['steps']} 步收敛")
```

### 2. 理解 Scaling 的直觉

```python
# 模拟 Scaling Laws：参数量与 loss 的关系
params = np.array([0.1, 0.5, 1.0, 3.0, 7.0, 13.0])  # 十亿
loss = 3.5 * params ** (-0.05)  # 幂律拟合

for p, l in zip(params, loss):
    print(f"参数 {p:.1f}B: loss ≈ {l:.3f}")
```

每次参数翻倍，loss 的改善幅度会递减——这就是 Scaling Laws 的幂律本质。

## 六、复杂度与边界

1. **预训练成本极高**
   - 训练一次数十亿参数的模型需要数千 GPU 小时
   - 这决定了只有大公司或研究机构才能做预训练

2. **数据质量比数据量更重要**
   - 重复、低质量的数据会降低模型能力
   - 数据清洗和去重是预训练的重要环节

3. **Scaling Laws 不是万能的**
   - 它描述的是"在给定计算预算下的最优分配"
   - 不是"模型越大就一定越好"
   - 小模型在足够数据下也能表现很好

4. **训练数据和测试数据不能重叠**
   - 数据泄漏是预训练评测中最严重的问题
   - 需要做去重和过滤

## 七、论文与真实系统映射

这一章的核心论文：

- **Scaling Laws for Neural Language Models**（Kaplan et al. 2020）：首次系统性地描述了模型参数、数据和计算量之间的关系
- **Training Compute-Optimal Large Language Models**（Chinchilla, Hoffmann et al. 2022）：修正了 Scaling Laws，指出了"计算最优"的训练策略

在真实模型里：
- GPT-3：175B 参数，300B token
- LLaMA：7B~65B，1.0~1.4T token（遵循 Chinchilla 规则）
- DeepSeek-V2：236B 总参数，8.1T 训练 token
