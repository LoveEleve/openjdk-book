## 十一、反伪洞察检查

每条“洞察”至少满足下面 3 条中的 2 条：
1. 能解释一个具体设计选择
2. 能解释一个具体风险 / 失败边界
3. 能帮助迁移到别的项目

否则它只是“看起来像懂了”的泛话。

## 十二、读者最终能力判据（Reader Outcome）

读完这个项目的源码分析后，读者至少应该能：

1. 解释这个项目为什么存在
2. 说清主线机制和横切专题
3. 指出最容易误解 / 误用的地方
4. 从症状回推风险边界
5. 把关键思想迁移到别的项目
6. 用自己的话复述主要设计而不是背 API

如果不能达到这些，就说明分析还不够好。

---

## 十三、最终输出标准

一份完整的项目分析至少应包含：
- 项目根问题
- 主线机制
- 横切专题
- 认知风险点
- 分析边界
- 前置认知桥
- 工程问题学习点
- 书级结构建议
- 可迁移思想
- 反伪洞察检查
- 读者能力判据

这套模板的目标不是“把源码讲完”，而是：
> **把读者真正带到“会分析这类系统”的状态。**
