# AI / 大模型 / Agent 理论学习方法论

> 用途：定义本卷理论内容如何讲、先讲什么、讲到什么深度，以及如何把公式、论文、实验和源码连成同一条学习链。

---

## 一、这不是知识点目录，而是一条可验证的依赖链

AI 知识最容易学成四种碎片：

- 只会背概念：知道 Attention、RAG、Agent，却不知道它们解决什么问题；
- 只会看公式：能推导矩阵，却不知道公式如何影响显存、延迟和系统边界；
- 只会读论文：知道论文贡献，却无法判断实验是否支持结论；
- 只会调框架：能调用 API，却不知道模型上下文、工具协议和恢复语义。

本卷采用一条依赖链：

```text
数学对象
  ↓
学习问题
  ↓
模型结构
  ↓
训练目标
  ↓
推理过程
  ↓
Agent 控制循环
  ↓
Runtime 状态与副作用
  ↓
论文、实验、源码相互验证
```

每个新概念必须回答：

1. 它建立在哪些前置知识之上？
2. 它解决了哪个具体问题？
3. 如果没有它，系统会怎样失败？
4. 它的输入、输出、状态和边界是什么？
5. 如何用公式、最小代码、实验或真实源码验证？
6. 它在下一个更大系统里扮演什么角色？

---

## 二、讲解深度分为四层

每个主题不追求一开始讲完所有细节，而是分四层逐步推进。

## L0：直觉层

回答：
- 这个东西是什么？
- 它解决什么问题？
- 为什么普通方案不够？

要求：
- 不依赖复杂公式；
- 用一个具体输入/输出例子；
- 说明最常见误解。

## L1：机制层

回答：
- 数据如何流动？
- 关键状态有哪些？
- 哪些分支会改变结果？
- 时间和空间复杂度是什么？

要求：
- 给出核心公式；
- 给出伪代码；
- 画出输入→变换→输出链路。

## L2：实现层

回答：
- 如何用最小代码实现？
- 内存如何布局？
- 并发、缓存、数值稳定性和错误如何处理？

要求：
- Python/TypeScript 最小实现；
- 至少一个可运行实验；
- 记录复杂度、边界和失败样本。

## L3：系统层

回答：
- 这个机制如何进入真实 LLM 或 Agent Runtime？
- 它与上下文、工具、权限、恢复、评测如何交互？
- 论文方案和生产系统哪里不同？

要求：
- 连接真实论文或源码；
- 对比至少两种设计取舍；
- 给出可迁移工程原则。

## 三、每篇文章固定采用“问题驱动 + 证据闭环”

每篇正文建议遵循以下结构：

### 1. 这一章真正的问题
不用“介绍 Attention”，而写成：
- 为什么模型需要根据上下文动态改变 token 表示？
- 为什么生成第 1000 个 token 时不能重新计算前 999 个 token？
- 为什么模型会调用工具却无法保证工具结果真实？

### 2. 最小前置知识
只补当前章节必需的知识，不把整本数学课塞进来。

格式：
- 已知：读者需要先理解什么；
- 本章补充：只讲哪些定义；
- 暂不展开：哪些内容留给后续章节。

### 3. 直觉方案为什么失败
先给一个看起来合理的方案，再展示它的失败：
- 全量重算 → 推理太慢；
- 把所有历史塞进 prompt → 上下文爆炸；
- 让模型自己宣布完成 → 验收不可信；
- 让每个工具自己判权限 → 边界不可治理。

### 4. 正式机制
给出：
- 对象定义；
- 核心公式；
- 状态机；
- 数据流；
- 不变量。

### 5. 最小实现
用足够短的代码验证主机制：
- 代码不是生产实现；
- 每段代码说明对应哪个公式或状态；
- 先保证可读，再讨论优化。

### 6. 实验与证据
实验至少包含：
- 假设；
- 输入；
- 对照组；
- 指标；
- 结果；
- 失败案例；
- 结论边界。

### 7. 论文与源码映射
明确区分：
- 论文原始方案；
- 后续工程改进；
- 当前项目实际实现；
- 本文的迁移判断。

### 8. 复杂度与边界
至少讨论：
- 时间复杂度；
- 空间复杂度；
- token/显存/网络成本；
- 数值风险；
- 并发风险；
- 安全风险；
- 失败后能否重试或恢复。

### 9. 连接下一章
每篇结尾回答：
- 当前机制给下一层提供了什么输入？
- 下一章为什么必须建立在这里之上？

## 四、理论、论文、实验、源码的四角验证

一个概念至少通过两个角验证，核心概念通过四角闭环。

```text
理论：公式和定义是否自洽
  ↘
论文：作者如何证明它有效
  ↗      ↘
实验：最小实现是否复现趋势 → 源码：生产系统如何处理边界
```

### 理论不能替代实验
公式正确不等于实现正确，尤其是：
- mask；
- shape；
- dtype；
- padding；
- cache；
- 并发；
- 截断。

### 论文不能替代源码
论文通常省略：
- 错误处理；
- 取消；
- 超时；
- 重试；
- 观测；
- 兼容性；
- 数据损坏；
- 权限边界。

### 源码不能替代理论
源码能告诉你“怎么做”，但不一定告诉你：
- 为什么这样做；
- 替代方案是什么；
- 复杂度为何合理；
- 结论能否迁移。

## 五、难度控制规则

### 规则 1：先建立可运行的窄闭环，再扩展广度
先完成：

```text
token → embedding → attention → logits → sampling
```

再进入：

```text
training → alignment → inference serving → agent loop → runtime
```

### 规则 2：公式只讲到能解释代码
不追求形式化证明的完整性，但必须能解释：
- 每个张量的 shape；
- 每个矩阵乘法的目的；
- 每个概率如何影响输出；
- 每个优化如何改变成本。

### 规则 3：每引入一个抽象，都给出失败模式
例如：
- Attention：二次复杂度；
- KV Cache：显存随序列增长；
- RAG：检索错、上下文污染；
- Tool Use：权限和副作用；
- Memory：错误事实长期化；
- Multi-Agent：协调成本和错误放大。

### 规则 4：不把模型能力和系统能力混为一谈
必须区分：
- 模型会生成什么；
- runtime 允许做什么；
- 工具实际做了什么；
- 系统如何验证已经做了什么。

### 规则 5：不把“模型自称”当作证据
所有完成、事实、工具结果和安全结论都必须说明：
- 来源是什么；
- 是否可验证；
- 是否有新鲜度；
- 失败时默认如何处理。

---

## 六、每个阶段的完成标准

### 阶段完成不是“文章写完”
而是读者能够完成三件事：

1. 用自己的话解释机制；
2. 写出或读懂最小实现；
3. 解释生产系统为什么需要额外的边界控制。

### 文章完成标准

- 有明确问题，而不是概念标题；
- 有最小前置知识；
- 有直觉方案和失败原因；
- 有公式/伪代码/数据流；
- 有实验或源码证据；
- 有复杂度和边界；
- 有与下一篇的依赖关系；
- 没有把推测写成事实。

---

## 七、一句话结论

> **本卷不是把 AI 名词讲得更多，而是把每个机制放回“问题—模型—训练—推理—Agent—Runtime—证据”的链条里，让读者既能理解论文，也能读懂源码，更能判断一个 Agent 系统为什么可靠或为什么会失败。**
