## 三、直觉方案为什么不够好

### 直觉方案 1：上线前做一次安全审查就够了

> 开发完做一次安全测试，没问题就上线。

问题：
- 安全是持续的过程，不是一次性活动
- 模型更新、工具更新、配置变化都可能引入新风险
- 攻击方式在持续进化

### 直觉方案 2：出了问题再补救

> 等安全事故发生了再处理。

问题：
- Agent 可以执行操作（写文件、调 API），比纯文本模型后果更严重
- 一次成功攻击可能造成不可逆的损失
- 事后补救成本远高于事前预防

## 四、正式机制

### 1. 安全治理的四个层次

```text
第 1 层：预防（Prevent）
  - 权限控制、沙箱、数据净化
  - 最小权限原则

第 2 层：检测（Detect）
  - 实时监控、异常行为检测
  - 审计日志

第 3 层：响应（Respond）
  - 告警、降级、阻断
  - 攻击溯源

第 4 层：恢复（Recover）
  - 回滚、快照恢复
  - 事后复盘
```

### 2. 生产监控要点

Agent 生产环境需要监控的关键指标：

```text
工具调用异常：调用频率突增、调用未被注册的工具
权限拒绝率：被拒绝的调用比例突然升高
输入异常：输入长度异常、包含可疑模式
输出异常：输出包含敏感信息
成本异常：token 消耗突然增加
```

### 3. 合规与审计日志

每个 Agent 调用都应该记录：

```text
谁：用户 id、session id
什么时候：时间戳
做了什么：完整调用链（输入 → 每一步 → 输出）
结果：成功/失败、错误信息
成本：token 消耗、工具调用次数
```

审计日志的基本要求：
- 不可篡改（append-only）
- 可追溯（从最终输出能追溯到原始输入）
- 保留足够时间（企业合规通常要求 90 天以上）

### 4. 最小可行安全治理清单

一个生产级 Agent 系统至少应该做到：

```text
1. 权限控制：action × resource，默认拒绝
2. 沙箱隔离：Agent 不能在任意目录写文件
3. 工具调用审计：每个工具调用都有日志
4. 输入净化：对用户输入和工具结果做净化
5. 审批机制：危险操作需要人工审批
6. 限流：防止单个 Agent 消耗过多资源
7. 监控告警：异常行为实时检测
8. 回滚机制：必要时能撤销操作
9. 定期评测：Agent 能力不退化
10. 安全更新：模型、工具、配置更新后重新评估
```

## 五、最小实现 / 伪代码

### 1. 审计日志

```python
import time

class AuditLog:
    def __init__(self):
        self.logs = []   # append-only

    def record(self, session_id, event_type, detail, result):
        entry = {
            "timestamp": time.time(),
            "session_id": session_id,
            "event_type": event_type,    # tool_call, permission, error, etc.
            "detail": detail,
            "result": result,            # success, denied, error
        }
        self.logs.append(entry)
        return entry

    def query(self, session_id=None, event_type=None):
        results = self.logs
        if session_id:
            results = [l for l in results if l["session_id"] == session_id]
        if event_type:
            results = [l for l in results if l["event_type"] == event_type]
        return results
```

### 2. 异常检测

```python
class AnomalyDetector:
    def __init__(self, audit_log, window_size=100):
        self.log = audit_log
        self.window_size = window_size
        self.thresholds = {
            "max_tool_calls_in_window": 60,     # 窗口内工具调用次数上限
            "max_permission_denied_rate": 0.3,  # 窗口内权限拒绝率上限
            "token_consumption_per_hour": 1_000_000,
        }

    def check(self, session_id):
        # 取最近 window_size 个事件作为检测窗口
        recent = self.log.query(session_id=session_id)[-self.window_size:]

        # 检查调用频率：窗口内工具调用次数是否过多
        tool_calls = [l for l in recent if l["event_type"] == "tool_call"]
        if len(tool_calls) > self.thresholds["max_tool_calls_in_window"]:
            return {"alert": True, "reason": "工具调用过于密集"}

        # 检查权限拒绝率
        denied = [l for l in recent if l["event_type"] == "permission"]
        if len(denied) > 0:
            rate = len([d for d in denied if d["result"] == "denied"]) / len(denied)
            if rate > self.thresholds["max_permission_denied_rate"]:
                return {"alert": True, "reason": "权限拒绝率过高"}

        return {"alert": False}
```

## 六、复杂度与边界

1. **安全治理是成本**
   - 每个安全措施都有成本（延迟、开发、维护）
   - 需要在安全性和可用性之间平衡

2. **合规要求因行业而异**
   - 金融、医疗、法律行业的合规要求更严格
   - 需要根据具体场景调整

3. **安全治理不是一次性的**
   - 模型更新、工具更新、配置变化后都需要重新评估
   - 需要建立持续的安全审查流程

4. **没有 100% 的安全**
   - 安全治理的目标是"把风险降到可接受的水平"
   - 不是"消除所有风险"

## 一句话结论

> **安全治理不是一次性活动，而是贯穿 Agent 系统生命周期的持续过程。预防、检测、响应、恢复四个层次缺一不可。最小可行安全治理清单包括权限控制、沙箱、审计日志、监控告警和回滚机制——没有这些，Agent 的能力越大风险越大。**
