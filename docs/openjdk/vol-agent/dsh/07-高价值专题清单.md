# dsh 高价值专题清单

> 用途：在第一卷主线与现有源码解析样本之外，列出下一轮最值得继续深挖的 dsh 专题。

---

## 一、优先级最高的 6 个专题

## 1. Tools 五事件执行管线
- 为什么优先：这是 dsh 把工具从“函数调用”提升成“事件协议”的核心位置。
- 推荐源码域：`core/tools`、`docs/subsystems/tools`
- 建议产出：`analysis/05-Tools五事件管线源码解析.md`

## 2. Session 持久化双后端
- 为什么优先：JSONL / SQLite 双后端最能体现“核心只发事件，持久化由插件订阅”的架构立场。
- 推荐源码域：`session/persistence-jsonl`、`session/persistence-sqlite`
- 建议产出：`analysis/06-Session双后端持久化源码解析.md`

## 3. Projection 五元契约
- 为什么优先：这是 dsh 把事件源转成用户可见状态和缓存状态的关键桥。
- 推荐源码域：`session/projection`
- 建议产出：`analysis/07-Projection五元契约源码解析.md`

## 4. Capability Seams 三角色
- 为什么优先：这是 dsh 最独特的架构 DNA，直接关系到“换 provider 换产品”。
- 推荐源码域：跨包 Service Definition / Provider / Consumer 模式、`docs/capability-seams`
- 建议产出：`analysis/08-CapabilitySeams三角色源码解析.md`

## 5. Profile / Bundle 六层层序
- 为什么优先：这是 dsh 把插件运行时装配成产品形态的入口。
- 推荐源码域：`boot/app-boot`、`bundle/`
- 建议产出：`analysis/09-ProfileBundle装配源码解析.md`

## 6. Sandbox / Subprocess 共享执行世界
- 为什么优先：它能把 dsh 的能力缝思想落到真实副作用边界上。
- 推荐源码域：`sandbox/`、`subprocess/`、`shell/`、`fs/`
- 建议产出：`analysis/10-共享执行世界源码解析.md`

---

## 二、一句话结论

如果继续深挖 dsh，最应该沿着：

> **tools → persistence → projection → capability seams → profile/bundle → shared execution world**

这条线往下走，因为它最能把 dsh 的“框架即产品”讲完整。
