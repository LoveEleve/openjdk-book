## 一、产品哲学(为什么"技术难学")

**难学的根源**(问题清单 #8-#19 的本质):
| 根源 | 现状 | 产品对策(写进书) |
|------|------|------------------|
| 报告式写作 | 书 = 平铺事实清单,读者看完不会用 | 教学叙事:问题先行,Why 先于 How |
| 顺序错误 | 章节顺序不按依赖,读者中途卡死 | 依赖拓扑排序(域发现产物) |
| 无比喻锚点 | 抽象概念无类比,记不住 | 类比锚点节(跨项目/生活类比) |
| 只讲正常路径 | 出事故不会排查 | 失效条件节(强制) |
| 专家直觉丢失 | "哪里值得警惕"没人讲 | 警惕点节(强制) |
| 不验证理解 | 读者以为懂了,实际幻觉 | 费曼式自测(章节末尾) |
| 知识不迁移 | 学会 A 不会 B | 类比轨(跨项目自动关联) |
| 无时间维度 | 兼容层当核心机制 | 时空溯源节(git 演进) |

**产品定义**:Agent 自主分析(引擎)+ 写书规范(本章)= 一本"让技术不再难学"的书。

## 二、域发现方法论工程化(00-域发现的完整代码化)

> 输入:原方法论 00(双锚点/入口展开/旁路/设计决策测试/🔴🟡分类/依赖图/对照验证)+ D18(体量排序)

### 2.1 入口自发现(D13)

```
目标:找到 {入口点类}.{方法}() 或等价物(不逼用户指定)
策略(按序尝试):
  1. README/docs "Getting Started" 示例 → 首次调用路径
  2. 构建文件:main 函数/启动类(pom.xml/package.json/go.mod/Cargo.toml/CMakeLists)
  3. 类名模式:Bootstrap/Starter/Main/Launcher/Factory/Application/Context/Engine
  4. 使用频率最高的公开 API(库/中间件无单一入口时)
  5. 全部失败 → 三档提问 B 档:推荐候选 + 证据 + 确认
产物:entrypoint 记录(类.方法 + 来源证据 file:line)
```

### 2.2 执行流展开(Level 0-3)

```
Level 0: 入口点(已定)
Level 1: 入口创建/配置/调用的对象 → 候选域
Level 2: Level 1 候选的创建/配置/调用 → 候选域
Level 3: 同 Level 2(展开到无新候选为止)
规则:沿公开/受保护边界,不钻私有实现细节
停止条件:某层零新候选
```

### 2.3 旁路扫描(独立子系统)

```
入口展开停止后,扫描未被访问的顶层源码目录:
  每个目录 → 设计决策测试(§2.4)→ 是域?→ 置信度中
示例:JVM 的 services/(JMX/JFR/SA)不被 CreateJavaVM 调用
```

### 2.4 设计决策测试(是域吗?二元过滤器)

```
是域吗?
├── 承载设计决策?
│   ├── 否 → ✂️ 排除(纯工具/委托封装/废弃/测试基建)
│   └── 是 → thin wrapper?
│            ├── 是 → ✂️ 排除
│            └── 否 → ✅ 域候选 → 分类(§2.5)
定量预检:包 ≥50 文件/单类 ≥500 行/≥3 子目录 → 必须读关键类再判定
```

### 2.5 🔴/🟡 分类(定义特征 + 三信号)

```
一级:没有这个域,框架是否失去定义特征?
  → 是 🔴 核心域 / 否 🟡 支撑域(多数应是 🟡)
二级:三信号验证(面试频率/生产频率/框架依赖)
  高=3/3 一致(AI 独立判定)/ 中=2/3(呈报+理由)/ 低≤1/3(用户决定)
定量打破僵局:≥100 文件或单类 ≥500 行 → 不可降级
```

### 2.6 依赖图 + 拓扑排序(教学顺序!直接进章节计划)

```
A 依赖 B = 不理解 B 的机制就无法理解 A 的行为/设计原因(机制级,非 import 级)
环形依赖 → 三轮化解策略(02 §1.4)
拓扑排序:叶子先 → Hub 其次 → 应用层最后 → 这就是书的章节顺序
```

### 2.7 对照验证(第九步,防止系统性遗漏)

```
已有执行计划/书籍 TOC → 构建基准域列表 → 对比:
  基准有/方法论缺 → 重读关键类 → 结论:排除正确(附理由)或新增域
  方法论有/基准缺 → 解释来源(入口展开?旁路?分类不同?)
覆盖率报告:基准域数 vs 方法论域数(≥80% 或系统性问题)
```

### 2.8 穷尽性核对(D18,体量排序)

```
find + wc -l(排除 test/vendor)→ top N 逐一核对:
  每个 top N 文件 grep 域发现产物 → 无覆盖 → 解释(遗漏/排除理由)
行数区间全覆盖:>5K / 1-5K / 600-1K / 400-600 / 200-400 / 100-200 / <100
收敛判据:top N 全部核对 + 子目录全扫 + 排除清单复核(不是"新增数为零")
```

**域发现产物**(→ 规格书章节计划):
```
域清单:🔴核心/🟡支撑 + 置信度
排除清单:类/包 + 排除原因(可追溯)
依赖图 + 拓扑序(教学顺序)
体量核对表:top N 文件 × 覆盖状态
```

## 二.9 工具使用原则(05 语义查询优先)

```
1. 语义查询优先:有语义索引(如 codebase-memory/ctags)先于纯 grep
2. grep 用于字符串字面量/错误消息/配置值(语义索引盲区)
3. 结论必须 file:line(工具输出即证据,禁止凭记忆)
4. 入口展开用"调用追踪"优先于"全文搜索"(执行流真实性)
5. 读设计文档优先于读实现(Pass 0 先于 Pass 1)
```

## 五、教学式书级产出规范(灵魂,章节生成器)

### 5.1 章节模板(B9 教学叙事引擎)

每章固定结构(章节 schema 强制):

```
chapter:
  meta:      { book, chapter_no, title, depth, target_reader, prereqs }
  opener:    问题先行(1-3 个本章要回答的问题)
              + "为什么学这章"(Why 先于 How)
  1. 概念引入(比喻锚点节:至少 1 个类比,跨项目或生活化)
  2. 机制讲解(Why → How:先设计动机,再实现细节)
     - 每个核心概念:定义 + 动机 + 源码证据(file:line)
  3. 关键流程(时序/状态机/数据流,配图即 ASCII 图)
  4. 失效条件节(强制):何时失效/什么条件下踩坑/怎么排查
  5. 警惕点节(强制):"为什么值得警惕"——资深直觉显式化
  6. 时空溯源节(可选,🔴A 深度强制):演进轨迹(git 溯源),
     兼容层 vs 核心机制辨析
  7. 费曼式自测(强制):3-5 题"用自己的话讲" + 参考答案要点
  8. 小结 + 下章预告(依赖链衔接)
```

### 5.2 读者模型(目标读者进规格书,写书时的约束)

```
reader_profile:
  level:        beginner | intermediate | advanced
  assumptions:  已懂什么(如 JVM 基础/Java 语法/并发概念)
  style:        引导式科普(默认) | 直接深入
写作约束:每个概念首次出现必须定义;用读者已懂的概念做类比;
         生僻词首次出现带一句解释。
```

### 5.2.5 学习目标轨(09 考点地图 + 11 模型侧知识)

```
goal:  book | interview | self_study
interview 目标时(对齐 C 档选择):
  - 生成考点地图:核心域 × JD 关键词(评测/可观测/Context/…)
    → 章节按考点组织强化(每章标注关联考点)
  - 面试弹药节:每章附"面试官会怎么问 + 怎么答"参考
self_study/book 目标时:
  - 学习内容规划:源码外必要知识轨(如 JVM 分析需懂编译器原理/
    KV Cache/GC 理论)——这些在源码里读不到,单独规划补充轨
  - 模型侧知识:标注"源码证据 + 模型侧解释"双来源(防幻觉)
```

### 5.3 教学叙事规则(章节生成器内置)

```
1. 问题先行:章节以问题开头(不是标题+定义)
2. Why 先于 How:先讲"为什么这么设计",再讲"怎么实现"
3. 依赖排序:前置概念已在前面章节讲过(拓扑序保证)
4. 比喻锚点:每个抽象概念至少 1 个类比(跨项目优先)
5. 主动讲解卡点:读者最可能卡住的地方,主动停下来讲
   ("你可能在想 X…实际上…")
6. 证据可见:每个结论紧跟 file:line(读者可跳回去核验——信任基础设施)
7. 渐进深度:能跟读 → 能复述 → 能推导(章节内三段式)
```

### 5.4 类比轨(跨项目知识迁移,B6)

```
知识库维护"机制-思想"索引:
  RSet 引用记录 ↔ Netty 内存池引用计数?同一思想 → 跨项目自动关联
触发:章节中出现已入库机制 → 自动附"类比锚点节"参考
延迟:分析完 2+ 项目后,类比轨才有效(知识库积累)
```

### 5.5 多视角(B5,规格书可选)

```
view:  single(default) | performance | concurrency | security | extensibility
多视角章节:同一机制按所选视角重讲(性能:热点/分配;并发:锁/竞争…)
```

## 六、规格书 schema(领域层扩展)

```
spec:
  meta:        { book_id, title, source_repo, version, target }
  goal:        一句话目标
  scope:       覆盖范围(域清单)
  non_goals:   显式不做(边界)
  reader_profile:  §5.2
  chapters:    拓扑序章节计划[{title, depth, kps[], prereqs[]}]
  views:       [single | performance | ...]
  success_criteria: [{id, description, required, evidence_ids[]}]
  allowed_operations: [read | run_demo | write_book]
  version:     spec 版本(变更 = 新 spec.admitted 事件)
```

## 七、验收判据(领域层,进验收器)

章节完成 → 验收器检查(三门串行的"确定性门"内容):

```
1. 覆盖:KPs 全部有对应章节内容(规格书 success_criteria 对账)
2. 深度:内容满足章节深度标准(§四)
3. 证据链:每个结论带 file:line,且 file:line 真实存在(grep 验证)
   ——无证据的结论 = 验收失败(反幻觉铁律)
4. 教学完整性:模板节齐全(问题先行/比喻锚点/机制讲解/失效条件/警惕点/费曼自测/小结——缺失任一小节 = 验收失败)
   ——缺失效条件节/警惕点节 = 验收失败(教学品质门)
5. 读者一致性:没有使用读者 assumptions 之外的概念而不解释
6. 运行时验证(涉及动态行为时):附 run-demo 验证记录或显式标注未验证
7. 收敛判定:连续 N 轮 review 无新增问题(支柱 4 程序化)
失败 → 失败消息带"为什么+怎么改" → 回注执行循环 → 自修 → 重验
连续失败 → 尝试超限暂停 → 问用户(降级回交互)
```

## 八、知识库语义(章节/结论/证据/验收状态)

```
book/
  spec.md            ← 规格书冻结快照(三合一:执行/验收/日志首条)

  {subject_key, conclusion, evidence_ids[], status: pinned|draft|superseded,
   source_version, verified: dynamic|static|unverified}
subject 冲突:同一知识点新结论更新旧结论(版本++,历史保留)
```

## 九、运行时验证(A1/A2,run-demo)

```
触发:章节结论涉及动态行为(多态分派/反射/SPI/线程模型/GC 行为)
流程:
  1. agent 生成最小复现 demo(规格书 allowed_operations=run_demo 授权)
  2. run-demo 工具:沙箱临时目录编译运行(学习模式允许临时区)
  3. 对账:静态结论 vs 动态输出(不一致 → 回炉修正静态结论)
  4. demo 产物入库(assets/demos/),验收器核对
无法验证(如需要集群/特殊环境)→ 显式标注 verified: unverified
```

## 十一、领域层状态机(章节级)

```
spec.admitted(规格书确认)
  → chapter.started(按拓扑序逐章)
  → chapter.analyzing(Pass 2 深度分析)
  → chapter.writing(章节生成,教学模板)
  → chapter.verifying(验收器:证据链/教学完整性/动态验证)
    → 失败 → chapter.revising(失败回注自修)→ chapter.verifying
    → 连续失败 → chapter.blocked(暂停问用户)
  → chapter.accepted(验收通过,结论入库 pinned)
  → chapter.completed(事件落库,下一章)
全部章节完成 → book.completed
非法迁移不可达(支柱 4:验收门 = 状态机强制)
```
