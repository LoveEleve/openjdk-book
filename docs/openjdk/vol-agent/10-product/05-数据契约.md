# 数据契约 — JSON Schema 全集

> 输入:04 领域层设计(规格书/章节/结论/验收/状态机)+ 01 引擎(事件溯源/知识库)
> 生成:2026-08-16
> 用途:产品所有持久化数据的单一真相源——事件日志/知识库/章节文件的 schema 定义
> 原则:①事件日志 = 追加写真相源(03);②模型可见⟺已记录(03 dsh 不变量);③writer 决定版本 bump(03);④schema 演进 = 新版本定义 + 旧版本可重放(03 OpenCode)

## 一、Schema 关系总览

```
spec (规格书,冻结快照)
 ├── reader_profile ──→ 章节生成约束
 ├── chapters[] ──────→ chapter (章节,模板结构)
 │                        ├── 结论结论携带 evidence_ids
 │                        └── acceptance (验收结果,留痕)
 └── success_criteria ──→ acceptance 判据来源

event (事件日志,真相源) ← 一切变更以事件写入,重放 = 真相
 ├── spec.admitted / spec.amended
 ├── chapter.started / analyzing / writing / verifying / revising / blocked / accepted / completed
 ├── conclusion.added / conclusion.superseded
 ├── acceptance.recorded
 ├── tool.executed (模型可见⟺已记录)
 ├── run_demo.verified
 ├── session.resumed
 └── book.completed

conclusion (结论条目,知识库) ← 由事件投影(投影器同事务)
```

### 事件类型全集(17 种,payload 定义)

| 事件 | 触发 | payload 关键字段 |
|------|------|-----------------|
| `spec.admitted` | 对齐完成 | spec(完整规格书,三合一首条) |
| `spec.amended` | 用户改目标 | spec_version, diff_summary(时间序更新,不重写基线) |
| `chapter.started` | 进入章节 | chapter_id, kps, depth |
| `chapter.analyzing` | Pass 2 深度分析 | chapter_id, findings[] |
| `chapter.writing` | 章节生成 | chapter_id, template_sections 完成度 |
| `chapter.verifying` | 验收开始 | chapter_id, criteria_ids[] |
| `chapter.revising` | 验收失败回注 | chapter_id, failures[](为什么+怎么改), attempt |
| `chapter.blocked` | 连续失败暂停 | chapter_id, attempt, reason(降级回交互) |
| `chapter.accepted` | 验收通过 | chapter_id, verdict, checks 汇总 |
| `chapter.completed` | 章节落库 | chapter_id, conclusions[] |
| `conclusion.added` | 结论入库 | subject_key, conclusion, evidence_ids, verified |
| `conclusion.superseded` | subject 冲突更新 | subject_key, old_revision, new_revision |
| `acceptance.recorded` | 验收留痕 | chapter_id, ok/scope(full\|targeted), checks[](fail-silent 审计) |
| `tool.executed` | 工具调用 | tool, args_summary, result_summary(模型可见⟺已记录) |
| `run_demo.verified` | 动态验证 | demo_id, status(pass/fail), output_summary, 对账结论 |
| `session.resumed` | 跨 session 恢复 | resume_from_seq, active_chapter, **handover_summary(7 段模板:Objective/Work State/Next Move/Relevant Files/Decisions/Open Questions/Pending)**——新 session 注入上下文(交接自动化 #21) |
| `book.completed` | 全书完成 | chapters_total, conclusions_total |

**损坏检测**(Pi reducer 12 种 + 重放校验):seq 不连续/类型未知/版本不兼容/payload 缺必填/分叉(同 seq 不同内容)→ 拒绝而非修复。

## 七、Schema 间关系与约束

```
1. spec.admitted 事件的 payload = 完整 spec(三合一,无第二份拷贝)
2. chapter 文件 = chapter.completed 事件的投影(重放可重建)
3. conclusion = conclusion.added 事件的投影(投影器同事务)
4. acceptance.recorded 永不清除(审计轨);spec.amended 后旧验收标 stale
5. tool.executed 事件:模型任何可见输入 ⟹ 新事件(dsh 不变量)
6. 所有事件 seq 单调;重放 = 真相;损坏 = 拒绝
7. schema 演进:type.version 递增,旧版本解码器保留(重放兼容)
```
