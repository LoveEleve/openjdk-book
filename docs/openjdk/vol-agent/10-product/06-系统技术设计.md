## 三、核心接口(能力缝三处 + 关键接口)

### 3.1 LLMProvider(LLM 层缝)

```ts
interface LLMProvider {
  readonly id: string
  /** 流式调用,消息 = 05 契约的事件投影消息 */
  stream(req: LLMRequest): AsyncIterable<LLMDelta>
  /** 结构化输出:JSON Schema 强制(验收器/规格书用) */
  generateObject<T>(req: LLMRequest, schema: JSONSchema): Promise<{ data: T; usage: Usage }>
  /** 工具调用回合(M3 实现):原生 function calling——tool_calls 元素带 type:"function",
      arguments 为 JSON 字符串(OpenAI 协议),tool 结果必须跟在带 tool_calls 的 assistant 消息后 */
  chatWithTools(req: ChatWithToolsRequest): Promise<ChatWithToolsResult>
}
interface LLMRequest {
  messages: Message[]            // { role: system|user|assistant|tool, content }
  model?: string                 // 默认 deepseek-v4-flash
  temperature?: number           // 验收器强制 0
  maxTokens?: number
}
```

### 3.2 ToolProvider(工具层缝)

```ts
interface ToolProvider {
  readonly name: string
  readonly schema: ToolSchema     // 参数 JSON Schema
  readonly permission: 'read' | 'write' | 'run'   // 学习/写书/验证分级
  execute(ctx: ToolContext, args: unknown): Promise<ToolResult>
}
interface ToolResult {
  ok: boolean
  output: string                  // 有界(截断 + 文件指针,输出托管)
  evidence?: Evidence             // file/lines/output_bytes/digest/exit_code
  error?: { kind: string; message: string }   // 失败进上下文(LLM 自纠)
}
```

## 四、核心时序(4 条主链路)

### 4.1 对齐流程(M2)

```
用户输入 → 6 维盘问(三档提问)
  A 档自答:入口点/版本/源码位置(环境自检)
  B 档推荐:深度/画像(带证据+理由)
  C 档决策:目标/产出形式
→ 规格书 JSON(generateObject 强制 schema)
→ 冻结快照 → 事件 spec.admitted(完整 spec)
→ 三合一:执行上下文(注入)/验收基准/知识库首条
用户中途改目标 → spec.amended(时间序更新,不重写基线)→ 旧验收标 stale
```

### 4.2 执行循环(M3,双层)

```
外层:章节队列(收件箱,拓扑序)
  chapter.started(事件)
内层:turn 循环(单章)
  turn 开始:上下文 = 规格书 + 前章结论(7 段摘要) + 本章 KP
  step:LLM 请求 → 工具调用 → 结算七步 → 失败进上下文
  tool.executed(事件,模型可见⟺已记录)
  收敛检测:连续重复调用(3/5/8 阈值 advisory)
  turn 结束:预算耗尽/无事可做/验收触发
崩溃恢复:重放日志 → 失败化 running 工具 → 从收件箱继续
```

### 4.3 验收流程(M4,三门串行 + 支柱 4)

```
章节写完(模板 8 节齐全)
→ 门 1(确定性):证据链(file:line 真实验证,含范围 2-3)/教学完整性(7 节标记全齐)/覆盖(KP 滑动窗口)/深度
   失败 → chapter.revising(失败消息带"为什么+怎么改")→ 修订循环(reviseText:LLM 修正)→ 重验
→ 门 2(LLM 独立审查,后置 M11):四隔离/温度 0/fail-closed
→ 留痕:acceptance.recorded(ok/scope,partial 不当全绿,fail-silent)
→ 收敛:连续 N 轮无新增 = 停止信号(isConverged 接入 verifyChapter 提前停)
→ 修订耗尽 → chapter.blocked(自动暂停,降级问用户)
非法迁移不可达:未验收的章节不能进入下一章(状态机强制)
```

### 4.4 恢复流程(M6,跨 session)

```
sca --continue / "继续分析 JVM"
→ 重放日志到 lastSeq(校验:seq 连续/损坏拒绝)
→ 投影恢复:当前章节状态/已验收结论/规格书版本
→ 7 段摘要注入上下文(Objective/Work State/Next Move…)
→ 从收件箱未完成章节继续
session.resumed 事件(携带 7 段 handover_summary)
交接 = 日志本身(无手写交接文档)
全书完成 → book.completed(章节/结论总数统计)
```

## 五、状态机实现(合法迁移表)

```
状态:ADMITTED → ANALYZING → WRITING → VERIFYING → ACCEPTED → COMPLETED
           ↘ REVISING(VERIFYING 失败)↗      ↘ BLOCKED(连续失败)

合法迁移表(非法迁移 = 拒绝,支柱 4):
| 当前 | 事件 | 下一状态 | 守卫 |
|------|------|---------|------|
| ADMITTED | spec.admitted(确认) | ANALYZING | 规格书完整性校验 |
| ANALYZING | chapter.analyzing 完成 | WRITING | 覆盖 KPs 确认 |
| WRITING | chapter.writing 完成 → chapter.verifying(验收开始) | VERIFYING | 模板 8 节齐全 |
| VERIFYING | 验收失败(attempt<N)→ chapter.revising | REVISING | 失败消息回注 |
| REVISING | 修正完成 | VERIFYING | — |
| VERIFYING | 验收通过 → chapter.accepted | ACCEPTED | 收敛判定(连续 N 轮无新增) |
| VERIFYING | 连续失败(attempt≥N)→ chapter.blocked | BLOCKED | 降级问用户 |
| ACCEPTED | 结论入库 → chapter.completed | COMPLETED | conclusion.added 成功 |
| COMPLETED | 下一章(拓扑序)→ chapter.started | (下一章 ADMITTED) | 拓扑序 |

禁止:ACCEPTED 前写结论/COMPLETED 前未验收/REVISING 直接 ACCEPTED/跳过章节
```

## 六、事件写入路径(事件溯源三支柱的代码结构)

```
appendEvent(type, payload):
  1. 校验:type 已知(17 种判别)+ payload 必填(05 schema)
  2. seq = 单写者计数器(内存单调,崩溃从文件尾恢复)
  3. 原子写:临时文件追加 + fsync + rename(崩溃只留 .tmp)
  4. 投影同事务:conclusion.added → 投影器更新结论库(失败 = 不提交)
  5. 返回 Event(含 seq)

replay(from=0):
  for evt in events:
    validate(seq 连续/type 已知/版本兼容/无分叉)
    损坏 → 拒绝(记录损坏原因,不静默修复)
    投影:chapter/conclusion 状态重建
```
