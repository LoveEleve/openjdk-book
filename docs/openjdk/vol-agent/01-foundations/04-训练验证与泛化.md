## 三、直觉方案为什么不够好

很多人第一次训练模型时，直觉是：

> 训练集上的 loss 一直降，说明模型在进步。

这个直觉在训练初期成立，但训练久了就会出问题。

真实情况是：

**模型可以"记住"训练集，但不"学会"规律。**

就像学生背答案：
- 考试碰到原题 → 满分
- 考试碰到新题 → 不会

所以必须把"训练时看到的数据"和"最终用来检验的数据"完全分开。

## 四、正式机制

### 1. 训练集、验证集、测试集

整个数据集必须分成三份，各有各的用途：

#### 训练集（train set）
- 用途：训练时用来更新参数
- 模型直接"看到"这些数据

#### 验证集（validation set）
- 用途：训练过程中用来调超参数、看中间效果
- 模型不直接在上面训练，但人会根据验证集结果做决策

#### 测试集（test set）
- 用途：训练结束后，最终检验模型是否真的会泛化
- 训练过程中完全不能碰

### 2. 为什么验证集和测试集必须分开

如果只用训练集和验证集：

```text
训练 → 看验证集 → 调参数 → 再训练 → 再看验证集 → ...
```

这个过程会让人"不知不觉地根据验证集调整决策"。

最终，验证集也变成了"隐式训练数据"。

所以必须有一个**从始至终没看过的测试集**，才能给出客观的泛化评估。

### 3. 欠拟合（underfitting）

欠拟合 = 模型太弱，连训练集都没学好。

表现：
- 训练集 loss 高
- 验证集 loss 也高

原因：
- 模型容量不够
- 训练不够
- 特征不够

### 4. 过拟合（overfitting）

过拟合 = 模型把训练集的细节、噪声、巧合都背下来了。

表现：
- 训练集 loss 很低
- 验证集 loss 很高

原因：
- 模型容量太大
- 训练数据太少
- 训练太久

### 5. 泛化（generalization）

泛化 = 模型在没见过的输入上也能给出合理输出。

这是训练的真正目标，不是"让训练集 loss 变成 0"。

影响泛化的因素：
- 训练数据量：越多越好
- 数据质量：越干净越好
- 模型容量：不能太小也不能太大
- 正则化：防止过拟合的技术

### 6. 数据泄漏（data leakage）

数据泄漏 = 训练数据中混入了测试数据的信息。

这是最严重的错误之一，因为它会让评估结果完全虚假。

常见形式：
- 测试集数据被不小心混入训练集
- 特征中包含了"未来信息"
- 评测时模型已经见过测试样本

在 Agent 评测中，数据泄漏特别危险：
- 如果 Agent 在训练时见过某个 GitHub issue 的解法
- 评测时再遇到这个 issue，它可能在"背答案"而不是"真解决"

## 五、最小实现 / 伪代码

### 1. 模拟过拟合

```python
import numpy as np

# 生成训练数据：10 个点
x_train = np.linspace(0, 1, 10)
y_train = 2 * x_train + 1 + np.random.randn(10) * 0.1

# 生成测试数据：5 个新点
x_test = np.linspace(0.1, 0.9, 5)
y_test = 2 * x_test + 1 + np.random.randn(5) * 0.1

# 用一个非常复杂的模型（高阶多项式）去拟合
# 训练集上几乎完美拟合
# 但测试集上表现很差
# 这就是过拟合的典型表现
```

### 2. 训练集 vs 测试集的表现对比

```python
# 模拟一个典型的过拟合训练过程
# 训练 loss 持续下降，但验证 loss 先降后升

training_loss = [2.0, 1.5, 1.0, 0.6, 0.3, 0.15, 0.08, 0.04, 0.02, 0.01]
validation_loss = [2.1, 1.6, 1.1, 0.7, 0.4, 0.25, 0.20, 0.22, 0.30, 0.45]

# 最佳停止点在第 6 步（验证 loss 最低）
best_step = 6
print(f"最佳停止步数：{best_step}（验证 loss = {validation_loss[best_step]}）")
print(f"训练 loss：{training_loss[best_step]:.2f}")
print(f"测试 loss：{validation_loss[best_step]:.2f}")
```

这里的关键是：
- 训练 loss 一直在降
- 验证 loss 先降后升
- 最佳模型在验证 loss 最低点，而不是训练 loss 最低点

## 六、复杂度与边界

1. **数据量决定模型上限**
   - 更多数据通常比更复杂的模型更有效
   - 数据质量比数据量更重要

2. **过拟合无法完全消除**
   - 只能通过正则化、数据增强、早停等技术来缓解
   - 永远不要追求"训练集 loss = 0"

3. **验证集不能被反复使用**
   - 每次看验证集都是在"泄漏信息"
   - 如果需要多次调参，应该分更多层

4. **测试集只能用一次**
   - 用完测试集后，就不能再调模型了
   - 否则测试集就变成了新的验证集

## 七、论文与真实系统映射

所有 AI 论文都遵循训练/验证/测试的分工。

- 论文实验结果表中的"测试集"必须严格独立
- 评测基准（如 TruthfulQA、SWE-bench、AgentBench）都定义了自己的测试集
- 数据泄漏是论文和评测中反复出现的严重问题

在真实系统里：
- 一个 Agent 在真实环境中运行，本身就是"测试"
- 它面对的问题，模型训练时很可能没见过
- 这就是为什么"泛化"是 Agent 系统最核心的挑战之一

如果你去看 `vol-agent` 现有的五个项目：
- 它们都在设计"测试契约"来验证系统行为
- 都在防止"模型自称完成 = 真完成"这种类似"过拟合"的错误
