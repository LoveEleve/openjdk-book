## 三、直觉方案为什么不够好

很多人第一次接触"模型输出"时，直觉是：

> 模型应该直接给出"正确答案"。

这个直觉在分类任务里可能成立（比如"是猫还是狗"），但一旦进入生成任务，立刻失效：

- "今天天气很好，我想去" → 后面可以接"公园""散步""游泳""吃冰淇淋"……都是合理的
- 模型应该"选一个"，还是"给出各种可能性"？

如果模型只输出一个答案，就会有下面几种严重问题：

1. 它不会告诉你"这个答案有多大把握"
2. 它不会提供"其他可能性"
3. 它不会让你知道"这个任务它其实不知道，只是被迫选了一个"

所以真正的模型输出不是"一个答案"，而是：

> **一个概率分布：对每个候选输出，给出一个概率。**

## 四、正式机制

### 1. 概率：从 0 到 1 的把握程度

概率 = 0 ~ 1 之间的一个数，表示"这件事有多大可能发生"。

- 概率 1 = 一定发生
- 概率 0 = 不可能发生
- 概率 0.7 = 十次里大概发生七次

全是基础，但有一个关键点：

> 所有候选概率加起来必须等于 1。

这就叫"概率归一化"。

### 2. 分布：谁各占多少

把每个候选结果和它的概率放在一起，就是"概率分布"。

举例，"下一个词"的分布：

```text
"公园"   0.4
"散步"   0.3
"游泳"   0.2
"吃冰淇淋" 0.1
```

- 每个候选≥0
- 加起来=1
- 概率最高的不一定是"唯一正确答案"

### 3. 为什么模型输出分布而不是确定答案

有三个原因：

#### 原因 1：语言本身就不确定
"明天天气怎么样" → 可以有很多合理回答。

#### 原因 2：模型不是全知
模型的知识有限，它也说不准。

#### 原因 3：分布允许采样
如果你想每次得到不同结果，就可以"按概率随机选一个"。
这就是后面要讲的 **sampling**。

### 4. 分数（logits）→ 概率（softmax）

模型内部其实不直接输出概率。

它先输出"分数"（logits），再通过 softmax 转成概率。

```text
分数：  公园 2.0    散步 1.2    游泳 0.5    海边 -0.3
                               ↓ softmax
概率：  公园 0.56   散步 0.25   游泳 0.13   海边 0.06
```

- 分数越高，概率越大
- 分数可以是负数，也可以是正数，没有上限
- softmax 保证所有概率加起来=1

### 5. 交叉熵：衡量"预测分布"和"真实分布"的差距

训练时，模型输出一个分布，但"真实答案"往往是一个确定词。

怎么衡量"模型分布"和"正确答案"之间的差距？

用**交叉熵（cross-entropy）**。

直觉理解：
- 如果模型对正确答案给的概率很高 → 交叉熵很小
- 如果模型对正确答案给的概率很低 → 交叉熵很大

为什么交叉熵特别适合语言模型？

因为交叉熵对"低概率"惩罚非常大：
- 如果正确答案概率是 0.9，交叉熵约 0.1
- 如果正确答案概率是 0.1，交叉熵约 2.3
- 如果正确答案概率是 0.001，交叉熵约 6.9

这会让模型急剧地、优先地把正确答案的概率提上去，而不是"慢慢平均分配"。

语言模型训练的目标，就是让交叉熵越来越小。

### 6. 概率高 ≠ 事实正确

这是最重要的一条边界。

**模型对某个答案给的概率高，只说明"根据训练数据，这个答案在这个上下文中很常见"。**

它不说明：
- 这个答案真的正确
- 这个答案符合事实
- 这个答案当前可用

所以后面我们会看到大量系统设计：
- 验证证据
- 独立审查器
- 完成判定
- 事实性评测

都是为了防止"模型概率高"被误认为"模型正确"。

## 五、最小实现 / 伪代码

### 1. 分数转概率

```python
import math

def softmax(scores):
    exp_scores = [math.exp(s) for s in scores]
    total = sum(exp_scores)
    return [s / total for s in exp_scores]

scores = [2.0, 1.2, 0.5, -0.3]
probs = softmax(scores)
print(probs)  # [0.56, 0.25, 0.13, 0.06]
```

### 2. 交叉熵

```python
def cross_entropy(true_index, probs):
    # true_index = 正确答案在列表里的位置
    return -math.log(probs[true_index])

probs = [0.56, 0.25, 0.13, 0.06]
print(cross_entropy(0, probs))  # 正确答案是"公园"，CE = 0.58
print(cross_entropy(3, probs))  # 正确答案是"海边"，CE = 2.81
```

交叉熵越小越好。

## 六、复杂度与边界

1. **概率分布不是答案**
   - 分布是"可能性"，不是"事实"
   - 不能把"概率高"当"一定正确"

2. **softmax 容易数值溢出**
   - 分数太大或太小，指数运算会出问题
   - 真实实现会用"减去最大值"的技巧

3. **交叉熵只关心正确答案**
   - 它不惩罚"错误答案的高概率"
   - 这是它被广泛使用但也有限制的原因

4. **分布不能解决所有问题**
   - 有些任务必须确定答案
   - 那时需要采样策略

## 七、论文与真实系统映射

这一章的理论基础，会出现在几乎所有 AI 论文和 Agent 系统里。

- 每篇论文实验结果：都基于概率分布和误差
- 每篇 Agent 论文：都会涉及"不确定性"和"判定"
- 每篇安全论文：都在防止"概率高"被误认为"事实正确"

在真实系统里：
- 完成判定：不能只看"模型觉得概率高"
- 权限检查：必须确定性，不能"概率化"
- 错误分类：需要区分"概率低"和"事实错误"
