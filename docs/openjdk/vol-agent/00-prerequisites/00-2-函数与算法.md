## 三、直觉方案为什么不够好

很多人对"程序怎么处理数据"只有一种模糊直觉：

> 就是跑一段代码，把数据变一变。

这个直觉过于含糊，无法回答下面的问题：

## 四、正式机制

### 1. 函数：一个很简单的规则

函数是：

> 给定一个输入，返回一个确定输出的规则。

用记号表示：

$$y = f(x)$$

意思是：
- $x$ 是输入
- $f$ 是这个规则
- $y$ 是输出

举例：

- `f(x) = x + 1`
  - 输入 3 → 输出 4
- `f(x) = x * x`
  - 输入 3 → 输出 9
- `f(name) = "你好, " + name`
  - 输入 "张三" → 输出 "你好, 张三"

注意：
- 函数不一定只能接受数字
- 它也可以接受文本、字典、列表
- 但输入、输出都必须是我们可以表示的数据

### 2. 复杂程序 = 简单函数的组合

大多数程序不是一个函数，而是很多函数套在一起：

$$z = f_3(f_2(f_1(x)))$$

举例：
1. 先把文本切分
2. 再把切分后的词转成数字
3. 再对数字求和

每一步都是一个小函数，三层叠起来就是一个完整处理。

这对神经网络极其重要：
> **神经网络本质就是一个巨大的函数组合：输入向量经过很多层变换，最后变成一个输出向量。**

### 3. 参数：函数的"旋钮"

有一个关键概念：同一个函数模板，可以通过"参数"产生不同行为。

例如：

$$f(x) = w \cdot x + b$$

- $w$ 和 $b$ 是参数
- 固定 $w,b$ 后，就是一个确定函数
- 改变 $w,b$ 后，函数行为就变了

这非常重要：

> **训练模型 = 调整函数里的参数，让这个函数在数据上表现得更好。**

"参数"就是后面"权重(weights)"和"偏置(bias)"的前身。

### 4. 算法：一步一步怎么算

如果说函数是"我要得到什么"，算法就是"我具体怎么一步一步算出来"。

算法 = 有限步骤 + 明确每一步 + 最终能结束。

举例：求一个数的平方。
- 错误理解：就写 $x^2$
- 算法理解：
  1. 取这个数
  2. 和自己相乘
  3. 返回结果

为什么算法重要？
因为计算机不会"直接看见结果"，它只会一步一步执行。

后面很多 AI 机制都必须按算法看：
- 怎么一步步变成概率
- 怎么一步步采样
- 怎么一步步搜索
- 怎么一步步完成一个 Agent turn

### 5. 复杂度：算法需要多少资源

两个算法做同一件事，可能花的时间、空间完全不同。

- 时间复杂度：大概要执行多少步
- 空间复杂度：大概要占多少内存

举例：
- 在一个列表里找元素：可能要遍历整个列表，复杂度随列表长度增长
- 直接知道下标取值：无论列表多大，都是常数时间

这章不要求会算，但必须建立直觉：
> **算法好坏，不是看"能不能跑通"，而是看"规模变大时还撑不撑得住"。**

后面 Attention 的 O(n²)、KV Cache 的显存增长，都是这种思维。

### 6. 确定性 vs 随机

- 确定性程序：同样的输入，结果永远一样
- 随机程序：同样的输入，结果可能不一样

AI 里两种都有：
- 推理时，如果要"大胆创造"，会用随机采样
- 但很多系统机制（比如权限、验证）必须确定性

提前记住一个关键词：**seed（随机种子）**。
同一套随机逻辑，如果 seed 固定，结果就能复现。

## 五、最小实现 / 伪代码

把前面串起来，写一个"两层函数组合"。

场景：
> 给一段文本，返回该文本是否包含"错误"导致的高风险。

先看懂逻辑，不一定要运行：

```python
def has_keyword(text: str, keyword: str) -> bool:
    return keyword in text

def risk_level(has_flag: bool) -> int:
    if has_flag:
        return 3   # 高风险
    return 0       # 低风险

text = "系统出现内存错误"
result = risk_level(has_keyword(text, "错误"))
print(result)   # 3
```

这里的核心：
- `has_keyword` 和 `risk_level` 是两个函数
- 我们是"组合"它们来处理输入
- 最后得到一个输出

这就是"用函数组合处理数据"的最简单版本。

## 六、复杂度与边界

这一章有几条边界必须记住：

1. **函数不能凭空知道答案**
   - 如果规则没有写，程序就不会得出结果
   - 这就是为什么 AI 不能靠"人肉枚举所有规则"来做

2. **参数决定函数能力**
   - 函数模板能力有限，参数决定它适配哪种输入
   - 后面会说：训练就是调参数

3. **确定性 vs 随机的边界**
   - 系统关键路径通常要确定性
   - 内容生成往往要随机性
   - 不能混为一谈

4. **复杂度的边界**
   - 一个算法在小数据上很好，不代表大数据也好
   - 这是后面无数优化论文（比如 FlashAttention）存在的理由

## 七、论文与真实系统映射

这一章没有专门论文，但它给所有内容提供语言。

在真实 Agent 系统里：
- 一个 Agent 的每一轮 = 函数组合
- 工具调用 = 一个函数，输入参数，返回结果
- 权限检查 = 一个确定性函数
- 完成判定 = 一个函数，看证据是否满足条件

如果你去看 OpenCode / Reasonix / Pi / Hermes / dsh 的源码：
- 所谓的"执行骨架"，本质就是一个不断调用函数、更新状态的循环
- 所谓的"工具协议"，本质就是定义好每个函数能收什么、返回什么

所以理解"函数 = 输入 → 输出"，是理解所有 Agent Runtime 的第一步。

## 一句话结论

> **函数是"输入到输出的规则"，算法是"怎么一步一步算出来"，参数是"可以调节的旋钮"，模型本质上就是这个三者的组合。理解这一点，后面神经网络、Transformer 和 Agent Loop 都没有本质上的新东西，只是在把函数组合得更深、更大、更可调节。**
