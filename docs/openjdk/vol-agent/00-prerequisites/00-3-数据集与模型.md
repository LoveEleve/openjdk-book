## 三、直觉方案为什么不够好

很多人第一次接触"机器学习"时，直觉是：

> 把问题和答案都记下来，模型以后再问就翻答案。

这个直觉错得很严重。

#### 为什么不好？

因为真实问题几乎不可能靠"背答案"解决：

- 新问题组合无穷无尽
- 输入稍微变一点，答案就不一样
- 真实数据往往是"看起来混乱"的

所以真正的学习目标不是：

```text
记住 (输入, 输出) 对
```

而是：

```text
找到一组参数，让函数输出的规律，能推广到没见过的输入
```

这是整章最重要的一句话。

## 四、正式机制

### 1. 数据集（dataset）

数据集 = 一堆样本的集合。

它通常被切成三部分：

- 训练集（train）
- 验证集（validation）
- 测试集（test）

### 2. 样本（sample）

一条数据就是一条样本。

例如，一条样本可能是：

```json
{
  "text": "系统出现内存错误",
  "label": "high_risk"
}
```

### 3. 特征（features）

样本里用来做判断的那部分叫特征。

在 NLP 里：
- 文本
- 词
- 长度
- 关键词

在表格里：
- 年龄
- 金额
- 时长

特征 = 模型真正"看得到"的输入。

### 4. 标签（label）

标签 = 我们希望模型输出的"正确答案"。

例如：
- = 高风险 / 低风险
- = 是猫 / 是狗
- = 下一句话是...

注意：
- 有些任务没有标签，叫"无监督"
- 但最核心的入门思路都先从"有标签"开始

### 5. 训练（training）

训练 = 根据样本反复调整参数，让函数输出越来越接近标签。

它大体是这样一个循环：

```text
喂输入
  → 函数算出输出
  → 对比标签，算出"差多少"（误差）
  → 根据误差调整参数
  → 再来一次
```

这个"差距"就是我们后面会讲的 **损失（loss）**。

### 5.5 训练循环里的更新公式从哪来

下一节的最小实现里会出现一个更新公式：

```python
w = w - learning_rate * error * x
```

这个公式不是猜的，它是**梯度下降（gradient descent）** 的一个简化版本。

它的直觉是：
- `error` 告诉我们当前输出偏了多少
- `x` 告诉我们在这次输入中，参数 w 对输出有多大影响
- 把两者相乘，就知道"w 应该往哪个方向调、调多少"

更完整的推导会在 `../01-foundations/02-梯度与反向传播.md` 里展开。
这里先接受它作为一个"按误差调整参数"的直观规则。

### 6. 为什么不是"背答案"

如果模型只记忆训练集，那么：
- 训练集上表现很好
- 一遇到新数据就崩

这两种情况分别对应：

#### 欠拟合（underfitting）
- 模型太弱，连训练集都没学好

#### 过拟合（overfitting）
- 模型把训练集的细节背下来了
- 包括噪声、错误、巧合
- 换新数据就失效

所以真正要追求的是：

> **泛化（generalization）：在没见过的输入上也能给出合理输出。**

### 7. 验证集和测试集为什么分开

- 验证集：训练过程中用来"调参/看中间效果"
- 测试集：训练结束后，用来"最终检验是否真的会泛化"

为什么要分开？
因为如果你一边训练一边看测试集，就可能"偷偷把测试集也学会了"。

这个在真实 Agent/LLM 评测里叫 **数据泄漏（data leakage）**，非常严重。

## 五、最小实现 / 伪代码

用一个极小的例子，说明"训练 = 调整参数让误差变小"。

场景：
> 给一个数 x，我们希望模型输出 "x * 2"。

我们有一个参数化函数：

```python
def predict(x, w, b):
    return w * x + b   # 一个非常简单的线性模型
```

初始化参数：

```python
w, b = 0.0, 0.0
```

训练循环（伪代码）：

```python
learning_rate = 0.01
for step in range(1000):
    x = 3
    target = 6            # 目标：3 * 2 = 6

    y = predict(x, w, b)  # 当前输出

    # 误差
    error = y - target

    # 非常简单的"按误差调整参数"
    w = w - learning_rate * error * x
    b = b - learning_rate * error

print(predict(8, w, b))   # 如果成功，接近 16
```

这里已经包含：
- 数据集里的一条样本 (x=3, target=6)
- 一个参数化函数
- 误差 = 输出 - 目标
- 按误差更新参数

真实训练还会更复杂，但核心骨架就是这个。

## 六、复杂度与边界

这一章有 4 条边界很重要：

1. 训练集 ≠ 测试集
   - 不能拿训练时的数据来吹成绩

2. 记住 ≠ 学会
   - 过拟合不是好消息

3. 特征决定上限
   - 如果特征根本不含区分信息，模型再好也白搭
   - "垃圾进，垃圾出"

4. 数据质量决定模型上限
   - 错误标签、缺失值、分布偏移，都会让结果不可靠

## 七、论文与真实系统映射

这章的基础概念会出现在几乎所有 AI 论文和真实系统里。

- 评测：
  - 几乎所有 AI 评测系统（后面会讲 TruthfulQA、SWE-bench、AgentBench 等）都在定义"测试集"
  - 用测试集证明"会泛化"，而不是"背答案"
- Agent：
  - 一个 Agent 在真实环境里跑，本身就是"测试"
  - 它面对的输入，模型训练时很可能没见过
- Runtime：
  - 数据泄漏、分布偏移、标签错误，在真实系统里会造成严重问题

如果你去看 `vol-agent` 现有的五个项目：
- 它们都在为"评测"设计测试契约
- 都在防止"模型自称完成 = 真完成"这种类似"记住答案"的错误

## 一句话结论

> **模型不是"背答案的程序"，而是一个参数化函数。训练就是调整参数让它在数据上误差变小，验证和测试用来检验它是否真的会泛化。真正的目标不是记住训练集，而是面对没见过的输入也能给出合理输出。**
