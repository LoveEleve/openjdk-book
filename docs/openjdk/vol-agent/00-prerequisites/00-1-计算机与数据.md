## 三、直觉方案为什么不够好

很多人第一次接触"计算机存数据"时，直觉是：

> 计算机就像人一样，能直接"记得"文字、图片、声音。

这个直觉在 AI 里特别危险。

因为如果计算机真的是"直接记得文字"，那它就不需要：
- 数字编码
- 分类
- 向量
- 概率
- 神经网络

所以我们必须先接受一个反直觉的事实：

> **计算机底层只认识两样东西：数字，以及对这些数字做运算。"

文字、图片、声音、文件、程序，最终都要先变成数字，才能被处理和存储。

## 四、正式机制：数据到底是怎么表示成数字的

### 1. 一切信息都可以被编码成数字

这是整章最重要的一个判断。

让我们从最原始开始看：

#### bit：最小的信息单位
- 计算机用 `0` 和 `1` 表示一切。
- 一个 `0/1` 就是一个 **bit**。

为什么只用 0 和 1？
因为硬件上最容易区分"通电/不通电"两个状态。

#### byte：8 个 bit 组成一个字节
- `10101010` 这样的 8 位，叫一个 **byte**。
- 一个 byte 能表示 $2^8 = 256$ 个不同状态。
- 一个英文字母通常占 1 个 byte。

#### 整数：把数字直接存成二进制
- `0` → `0`
- `1` → `1`
- `2` → `10`
- `3` → `11`
- `5` → `101`

这就是"二进制"：逢二进一，和十进制"逢十进一"同理。

#### 浮点数：表示小数
- 计算机表示小数会用"科学计数法 + 有限精度"。
- 例如 `3.14` 会被存成一个近似值，而不是精确值。
- 后面我们会反复遇到"浮点数近似"这个坑。

### 2. 文本是怎么变成数字的：字符编码

计算机不能直接存"汉字"或"字母"。

它必须给每个字符一个编号。

这就是字符编码。

#### 常见编码
- `Unicode`：一个字符一个编号，能覆盖几乎所有语言。
  - `'A'` 是 65
  - `'你'` 是一个更大的编号
- `UTF-8`：把 Unicode 编号变成一串 byte。
  - 英文通常 1 byte
  - 中文通常 3 byte

所以：
- 文本本质上是一个数字序列。
- "hello" 会先变成一组编号，再变成 byte。

这对 AI 极其重要：
> **在模型眼里，文本不是句子，而是一串数字编号。**
我们后面《Tokenizer 与 Embedding》会专门讲这个。

### 3. 结构化数据：列表、字典、表格、JSON

光有文本还不够，我们还经常需要"结构化"数据。

#### 列表
按顺序放一组东西：
```text
["苹果", "香蕉", "橙子"]
```

#### 字典
用名字去取值：
```text
{"name": "张三", "age": 30}
```

#### 表格 / 数据集
一行是一条记录，一列是一个字段：
```text
姓名   年龄   是否付费
张三   30     是
李四   25     否
```

#### JSON
一种把"列表/字典/数字/字符串"都串起来的结构，很多人叫它"数据的通用语言"：
```json
{
  "users": [
    {"name": "张三", "age": 30},
    {"name": "李四", "age": 25}
  ]
}
```

后面所有数据、样本、请求、响应，都会大量使用这种结构。

### 4. 程序到底在做什么

现在我们可以给"程序"一个准确表述：

> **程序 = 一系列指令，告诉计算机：输入哪些数据、对数据做哪些运算、把结果放在哪里。**

程序运行时的核心要素是：
- **输入**：外界给进来的数据
- **处理**：对数据做运算
- **输出**：处理后给出去的结果
- **状态**：程序在执行过程中记住的东西

这也是后面讲 Agent 时会反复遇到的一对核心概念：
- 一个 Agent 循环，本质就是"读输入 → 处理 → 输出 → 更新状态 → 再看有没有新输入"。

## 五、最小实现 / 伪代码

我们用一个极小例子，把这一章的东西串起来。

需求：
> 读一批用户数据，统计付费人数。

假设数据是这样：
```python
users = [
    {"name": "张三", "age": 30, "paid": True},
    {"name": "李四", "age": 25, "paid": False},
    {"name": "王五", "age": 28, "paid": True},
]
```

代码（可以不运行，先看懂）：
```python
paid_count = 0
for user in users:          # 遍历列表
    if user["paid"]:        # 检查这个用户的付费字段
        paid_count += 1     # 是 True 就加一

print(paid_count)           # 输出结果
```

这里你已经看到：
- 数据 = 一个列表 + 字典
- 处理 = 遍历 + 判断 + 计数
- 输出 = 在终端打印
- 状态 = 一个变量 `paid_count`

这种"读数据 → 处理 → 出结果"的小循环，是所有 AI 和 Agent 的最小雏形。

## 六、复杂度与边界

这一章不涉及性能，但有一个必须记住的边界：

> **所有"看起来智能"的东西，底层都是数字和运算。**

这带来三个重要推论：

1. 精度有限
   - 浮点数近似
   - 文本编码有多种
   - 同一个信息可能表示成不同数字

2. 数据质量决定上限
   - 如果数据集脏、错、缺，程序的结果就不会可靠
   - 这是后面讲"数据质量决定模型上限"的起点

3. 解释权在于人
   - 一个数字序列本身没有"含义"
   - 是我们给它赋予含义
   - 后面讲 Embedding 时，这会变得极其关键

## 七、论文与真实系统映射

这一章太基础，没有专门论文。

但它对应的真实系统能力，到处都是：
- JSON 是几乎所有 API 的数据格式
- 文本编码影响 tokenizer 设计
- 数据结构（列表/字典/表格）直接对应 Agent 的状态和工具参数

如果你去看真实 Agent Runtime：
- 一个 API 请求，本质是 JSON
- 一个工具参数，本质是字典
- 一条会话记录，本质是列表

所以这章不是"科普废话"，而是整个教材的第一块地基。
