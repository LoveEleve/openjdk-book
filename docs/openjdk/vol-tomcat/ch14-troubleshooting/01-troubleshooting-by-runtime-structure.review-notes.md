# Tomcat Ch14-01 故障排查专题 — review notes

## 第一轮：事实审

### 目标
核对：
- 本篇回溯前文哪几条主线，是否与整卷已完成正文一致
- 是否把“主线定位框架”误写成“已有具体案例已被证明”的硬断言
- 是否混淆了 Tomcat 本体问题和应用/依赖把主线拖坏的问题

### 当前需核对的关键结构锚点
- 启动链：Boot 集成桥 + Tomcat 启动主线
- 入口链：Connector / ProtocolHandler / Endpoint / Processor
- 执行链：Mapper / Valve / FilterChain / Servlet
- 偏离链：AsyncStateMachine / AsyncContextImpl / ErrorReportValve
- 状态链：Session / Manager
- 退场链：WebappClassLoaderBase / clearReferences

### 初步判断
- 当前正文主线与整卷前文是一致的，没有凭空发明新的排障分类
- 本篇最大的事实风险不在类名写错，而在于是否把“结构定位框架”写得像现成排障定理
- 目前结构上已经避免了“Tomcat 故障 = 容器自己问题”这一误判，这是对的

## 第二轮：因果审

### 目标
检查正文中所有“为什么故障最后总要回主线”“为什么不能先搜异常名”这类判断，是否真有前文主线支撑。

### 当前因果链
1. 故障现象虽然很多，但重要主线并不多
2. 关键词/异常名只能给入口，不能自动给结构位置
3. 连接打满、线程耗尽、慢请求等经常是跨链传播的结果
4. 类加载器泄漏和退场失败要回退场链，不该只盯 GC
5. 排障真正依赖的是“先分主线”的能力

### 当前风险
- 这篇如果不够克制，容易把“主线定位框架”写成“万能诊断口诀”
- 对“慢请求不能只甩锅给 SQL 或下游”的判断，要持续保持“需要先回执行链定位”而不是否认 SQL/下游可能是根因

## 第三轮：结构审

### 目标
检查结构是否遵守“困惑 -> 失败方案 -> 总图 -> 主线逆向定位 -> 收网”的方法论，而不是退化成故障清单。

### 当前结构评价
当前结构是：
1. 困惑开场
2. 失败方案
3. 最小总图
4. 启动失败 -> 启动链
5. 连接打满 / 线程耗尽 -> 入口链 / 执行链
6. async/timeout/错误页 -> 偏离链
7. 类加载器泄漏 -> 退场链
8. 慢请求 -> 执行链
9. 收网总结
10. 卷级阶段性收口

### 当前结构优点
- 没有退化成命令表或事故列表
- 先立“主线少于现象”的视角，再做逆向分类
- 卷级收口放在最后，结构上合理

### 当前结构风险
- `慢请求` 一节如果后续补太多案例，容易重新滑成性能篇补充
- 卷级收口段如果过长，容易把单篇正文结尾写成项目总结
