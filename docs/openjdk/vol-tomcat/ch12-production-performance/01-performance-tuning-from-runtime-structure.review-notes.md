# Tomcat Ch12-01 生产性能专题 — review notes

## 第一轮：事实审

### 目标
核对：
- 本篇引用前面主干与补深篇的结构结论，是否与已完成正文一致
- 是否把“结构上合理的推断”误写成“已有源码逐条证明的断言”
- `file:line` 若未新增，是否明确表明在复用前文已压实锚点

### 当前需核对的关键结构锚点
- 连接入口：Connector / ProtocolHandler / NioEndpoint / Http11Processor
- 执行链：Mapper / Valve / FilterChain / Servlet
- 偏离路径：AsyncStateMachine / AsyncContextImpl / HostValve / ErrorReportValve
- 长期运行边界：Session / WebappClassLoaderBase / clearReferences 等

### 初步判断
- 当前正文主线与整卷前文是一致的，没有凭空创造新主线
- 本篇最大的事实风险不在“讲错一个类”，而在“会不会把前文已经建立的结构关系说得比证据更硬”
- 因为这篇更像桥接篇，允许复用前文结论，但要避免把桥接性的归纳写成新发现

## 第二轮：因果审

### 目标
检查正文中所有“为什么线上数字会回到结构问题”这类判断，是否真有前文主线支撑。

### 当前因果链
1. 连接、线程、队列不是三个孤立现象，而是一条请求链的不同观察面
2. 执行链会直接投影成延迟与吞吐问题
3. async 不是天然优化，而是压力重分布
4. Session 与类空间退场问题会在长期运行中累积成性能与稳定性压力
5. 参数只是结构问题的外部旋钮

### 当前风险
- 这些结论方向是对的，但本篇很容易滑成“看起来什么都有关”，因此每个结论都要尽量回落到前文哪一条主线，而不是泛泛而谈
- “async 会转移压力”这句最需要克制，不能写成无条件结论，应该持续保留“可能 / 取决于设计”的口吻

## 第三轮：结构审

### 目标
检查结构是否遵守“困惑 -> 失败方案 -> 总图 -> 结构拆解 -> 收网”的方法论，而不是退化成参数专题列表。

### 当前结构评价
当前结构是：
1. 困惑开场
2. 失败方案
3. 最小总图
4. 连接、线程、队列是一条链
5. 执行链与延迟/吞吐
6. Session 的性能投影
7. async / timeout 的压力转移
8. 类空间与长期运行负担
9. 参数是结构问题的外部旋钮
10. 收网总结
11. 下篇桥接

### 当前结构优点
- 没有退化成参数表
- 没有写成一堆线程池/连接器经验结论
- 能把前文多个主题重新投影到“线上性能现象”上

### 当前结构风险
- 当前结构跨域很多，如果每节都想讲太全，很容易失焦
- `Session`、`类空间退场` 两节在篇中后段，若写得过重，读者可能觉得“是不是跑题了”

## 第四轮：读者审

### 目标
检查读者是否真能从“参数表思维”切到“结构瓶颈思维”。

### 当前读者收益
读完后，读者至少应能回答：
- 为什么性能问题不能只看参数
- 为什么连接、线程、队列是同一条链上的表现
- 为什么执行链和偏离路径都能变成线上性能现象
- 为什么长期运行边界也会反向影响性能

### 当前读者风险
- 如果读者前面几篇没读，这一篇会显得跨度大
- 如果没有少量硬锚点提醒“这些都来自前文具体源码”，读者可能觉得这是一篇纯经验归纳文
