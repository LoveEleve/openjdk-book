## 结论

Vol-02 的正文重写主线已经实质完成。

当前卷 2 已经形成一套从 HotSpot 基础对象、内存、类元数据、解释器、JIT、代码缓存、线程与 safepoint，到 GC、JNI、JVMTI、JFR、JMX、Attach、网络 I/O、Serviceability Agent 和运行时工具的连续源码阅读路径。

当前不应再把主要精力放在“继续寻找下一篇原稿”上。后续工作应从正文重写切换到收官维护：校验、导航、索引和版本演进。

## 已达到的标准

- 文章以真实读者困惑为入口，而不是按源码文件目录翻译。
- 关键章节普遍包含失败方案、角色关系、状态转换和设计取舍。
- 正文即使删去代码块，主叙事仍然成立。
- 关键机制绑定 OpenJDK 11u 源码文件与行号。
- 已多轮修正生成文件、平台差异、旧版实现残留和跨篇链接问题。
- 主要卷 2 域已经完成正文重写与 review；剩余少数历史文章缺少统一命名的 review 提交记录，但不等于正文未完成。

## 不再作为正文缺口处理的项目

以下情况属于流程性差异，不应误判为待重写文章：

- 文章已经有成文提交，但没有名为 `REVIEW` 或“深审”的独立提交。
- 文章缺少早期统一格式的 `*.rewrite-plan.md`，但正文已经按同一方法论完成并经过源码核查。
- 自动脚本按提交关键词识别文章状态时，把已完成文章误报为 raw。

判断文章是否完成时，应优先看正文结构、git 历史中的成文/纠偏记录，以及源码事实核查结果，不能只看单个文件名或单个提交关键词。

## 可选的流程性收尾

如果需要形式上进一步统一，可按以下顺序处理：

1. 对少数早期文章补齐 `*.rewrite-plan.md`。
2. 对缺少显式 review 提交标记的文章补一次轻量 review 记录。
3. 做一次全卷终检：禁用词、相对链接、`file:line`、Docsify 根路径和 `git diff --check`。

这些工作不会改变卷 2 的正文主线，只是让交接和自动化盘点更整齐。
