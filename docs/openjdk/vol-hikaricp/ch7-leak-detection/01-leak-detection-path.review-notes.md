# HikariCP Ch7-01 连接泄漏检测 — review notes

## 第一轮：事实审

### 目标
核对：
- `ProxyLeakTask` / `ProxyLeakTaskFactory` 的角色归属是否准确
- 借出时埋点、归还时取消、超时时告警这三段是否有对应源码支持
- 是否把“检测”写成“自动恢复”

### 当前需核对的关键锚点
- `ProxyLeakTask`
- `ProxyLeakTaskFactory`
- 借出时 schedule 的关键锚点
- `close()` 取消泄漏任务的关键锚点
- 超时告警 / unleaked 日志相关锚点

### 初步判断
- 当前主线与 Ch7 规划一致：借出埋点 -> 使用期观察 -> 归还/告警分支
- 没有把泄漏检测误写成池内轮询，这是对的
- 当前最大事实风险在于：借出时 schedule、归还时 cancel、超时告警这三段还没有被压到方法级锚点

## 第二轮：因果审

### 目标
检查正文中所有“为什么必须在借出时埋线索”“为什么 close 也是泄漏检测主线的一部分”这类判断，是否由源码结构支撑。

### 当前因果链
1. 池不能靠事后扫状态来完整定位是谁借了不还
2. 所以借出时就必须埋诊断任务
3. 归还时必须显式取消，不然就会制造误报
4. 超时告警的核心价值在于暴露责任，而不是自动修复连接

### 当前风险
- 这几条判断方向是对的，但如果不补 schedule/cancel/logging 的硬锚点，容易显得像设计推测
- “泄漏检测是诊断链不是恢复链”这句要继续保持克制，不要顺手暗示池会做超出源码事实的恢复动作

## 第三轮：结构审

### 目标
检查结构是否遵守“困惑 -> 失败方案 -> 总图 -> 诊断链拆解 -> 收网”的方法论，而不是退化成 leakDetectionThreshold 配置说明。

### 当前结构评价
当前结构是：
1. 困惑开场
2. 失败方案
3. 最小总图
4. 借出时为什么先埋线索
5. `ProxyLeakTask` / Factory
6. `close()` 为什么也在主线内
7. 超时告警为什么是责任暴露
8. 收网总结
9. 下篇桥接

### 当前结构优点
- 没有退化成参数文档
- 把“借出后的诊断生命史”作为单一主概念立住了
- 和借出/归还主线衔接自然

### 当前结构风险
- 如果后续补源码时不够具体，`ProxyLeakTask` 这一节会显得偏概念
- `close()` 作为诊断链的一半，这个说法很值钱，但也最需要硬锚点托底

## 第四轮：读者审

### 目标
检查读者是否能从“超时告警”切到“借出后的诊断生命史”这个视角。

### 当前读者收益
读完后，读者至少应能回答：
- 为什么池能在连接离开之后继续追踪它
- 为什么泄漏检测不是超时检查的别名
- 为什么归还时取消任务和借出时挂任务同样关键

### 当前读者风险
- 如果方法级锚点不足，读者会认可整体概念，但未必能确认这真是当前实现
- 如果后续精修时把 `ProxyLeakTask` 讲得太像“通用定时器技巧”，会冲淡这条诊断链的独特性

## 第五轮：边界审

### 目标
检查本篇是否提前透支 metrics/JMX/告警体系，或是否漏掉本篇必须收住的边界。

### 当前边界控制
本篇明确不深讲：
- metrics/JMX 总体体系
- 生产监控平台整合
- 连接借出/归还完整细节（前文已讲）

### 当前边界风险
- 如果为了说明告警而展开太多指标/监控集成，会吃掉后续 JMX/metrics 专题
- 如果为了说明借出埋点而重讲太多借出链，也会把前文重新吃回来

## 第六轮：依赖审

### 目标
检查前置依赖与后续桥接是否清楚。

### 前置依赖
- 强依赖借出链：因为诊断任务是在借出时挂上的
- 强依赖归还链：因为取消任务发生在 close 侧

### 后续桥接
- 当前桥接到 JMX 与运行时管理是合理的：泄漏检测讲的是诊断支线，下一篇可以接着讲“池还有哪些状态能被外部直接观察和管理”

## 当前结论

这篇已经完成一次性深审收口，当前主问题已从“结构是否成立”收敛为“借出埋点 / 归还取消 / 超时告警三段是否有足够硬的实现锚点”。本轮补强后，这个缺口已经被明显压实：
- `HikariPool` 借出时 schedule：`HikariPool.java:179`
- `ProxyLeakTaskFactory.schedule(...)`: `ProxyLeakTaskFactory.java:38`
- `ProxyLeakTask.schedule(...)`: `ProxyLeakTask.java:68`
- 超时 warn 日志：`ProxyLeakTask.java:75`
- `ProxyConnection.close()` 里 cancel：`ProxyConnection.java:246`
- `ProxyLeakTask.cancel()` 的 `unleaked` 提示：`ProxyLeakTask.java:88`

这让“泄漏检测是一条借出后的诊断生命史”这条主论断，不再只是结构解释，而有了完整的方法级托底。
