# 先读这一篇：怎样阅读这卷 HikariCP 源码分析

> 本文不是具体机制正文，而是整卷导读。它回答的问题是：**这卷到底在讲什么、按什么顺序读、为什么这些篇目会这样组织。**

## 这卷不是在讲“连接池参数”，而是在讲“连接的一生”

如果只看目录，你会看到：
- 总骨架
- 借出链
- 归还/驱逐链
- ConcurrentBag
- 生命周期 / HouseKeeper
- 连接验证
- 泄漏检测
- JMX
- metrics

如果没有导读，读者很容易把这卷误解成两种东西之一：

### 误解 1：这是一本连接池参数百科
不是。

这卷真正讲的是：
- 一条 JDBC 连接在池里如何出生、被借出、被归还、继续活着、被判断、被观察、被控制、最终退场

### 误解 2：这是一些零散优化点合集
也不是。

这卷里的很多主题看上去像散点：
- `ConcurrentBag`
- HouseKeeper
- leak detection
- JMX
- metrics

但它们不是彼此平行的小技巧，而是围绕同一条连接生命史的不同控制面。

## 这一卷真正要建立的，不是类名记忆，而是 3 层视角

### 1. 主干层
回答：
- 连接池骨架是什么
- 连接怎么借
- 怎么还
- 怎么在池里继续活

### 2. 并发与生命周期补强层
回答：
- 借还为什么能高并发协作
- 后台谁在管连接余生

### 3. 诊断与可观测层
回答：
- 候选连接怎样被验证为可交付连接
- 借出去太久不还怎样被发现
- 运行时怎样被观察和控制
- 指标怎样把生命史量化成可观测信号

所以这卷的组织逻辑不是“按包讲”，而是：

**先立连接生命史，再补支撑这条生命史的并发结构和诊断控制面。**

## 这一卷按“连接的一生”来排，顺序其实很自然

### 第一阶段：它怎么被装起来并活起来
- `Ch1` 总骨架

### 第二阶段：它怎么被借出去、被还回来
- `Ch2` 借出链
- `Ch3` 归还 / 驱逐链

### 第三阶段：它怎样在高并发下被协调借还
- `Ch4` ConcurrentBag

### 第四阶段：它归还后怎样继续活着
- `Ch5` 生命周期 / HouseKeeper

### 第五阶段：它怎样被验证、诊断、控制、量化
- `Ch6` 验证
- `Ch7` 泄漏检测
- `Ch8` JMX
- `Ch9` metrics

所以，这卷其实讲的是一条很完整的链：

```text
配置出生
  -> 借出
    -> 使用
      -> 归还 or 驱逐
        -> 池内继续活着
          -> 被验证 / 被告警 / 被控制 / 被量化
```

## 如果你是第一次看这卷，建议怎么读

最稳的顺序就是：
1. `Ch1` 总骨架
2. `Ch2` 借出链
3. `Ch3` 归还 / 驱逐链
4. `Ch4` ConcurrentBag
5. `Ch5` 生命周期 / HouseKeeper
6. `Ch6` 验证
7. `Ch7` 泄漏检测
8. `Ch8` JMX
9. `Ch9` metrics

这个顺序的好处是：
- 先建立主骨架
- 再压实前后半链
- 再补并发存储层
- 最后补诊断、控制和观测

## 如果你只想快速抓住核心

那最小主干是：
- `Ch1`
- `Ch2`
- `Ch3`
- `Ch5`

因为这四篇已经足够让你知道：
- 连接池不是容器
- 借出和归还是生命史前后半段
- 连接归还后生命史还没结束

## 如果你关心线上问题，怎么用这卷

- 借不到连接：先看 `Ch2`
- 归还后状态错乱 / 异常驱逐：先看 `Ch3`
- 高并发下承压与争用：先看 `Ch4`
- 长时间运行后连接寿命、后台维护：先看 `Ch5`
- 候选连接为什么被拒绝交付：先看 `Ch6`
- 连接借出去不还：先看 `Ch7`
- 运行时状态怎么查、怎么控：先看 `Ch8`
- 持续指标怎么观测：先看 `Ch9`

## 这卷最不该怎么读

### 1. 只挑自己眼熟的类看
比如只看：
- `HikariPool`
- `ConcurrentBag`
- `ProxyLeakTask`

会知道一些细节，但拼不回整条连接生命史。

### 2. 一上来只看 metrics / JMX / 泄漏检测
这样会知道怎么观察，但不知道你看到的那些信号到底对应生命史哪一段。

### 3. 把这卷当成 Spring Boot DataSource 配置手册
这卷当然和 Boot 有边界，但主线不在“怎么配”，而在“配好之后池内部怎么跑”。

## 到这里，这卷真正建立起来的是什么

如果把整卷压缩成一句话，它真正建立起来的不是“几个连接池类怎么协同”，而是：

**一条 JDBC 连接在 HikariCP 里的一生。**

也就是说：
- 它怎样被创建
- 怎样被借出
- 怎样被归还
- 怎样被继续活着
- 怎样被判断是否还能继续活
- 怎样被发现泄漏
- 怎样被控制
- 怎样被持续量化观察

## 读完这篇之后该做什么

如果你是第一次进这卷：
- 先按 `Ch1 -> Ch9` 顺着读

如果你是带着问题来的：
- 先在 `README.md` 看篇章职责
- 再回到对应那篇主线看

如果你接下来还要继续扩卷：
- 再补一份总图 / 总索引，会更利于回查与跳读
