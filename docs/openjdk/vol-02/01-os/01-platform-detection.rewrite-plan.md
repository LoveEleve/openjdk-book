## 1. 读者困惑

一个只有几十 KB 的 `java` 启动器，为什么一启动就能立刻做出这么多“看起来像是很懂机器”的决定？

更具体地说：

- JVM 怎么知道自己跑在什么内核上？
- JVM 怎么知道 CPU 支不支持某条指令？
- JVM 怎么知道自己在容器里其实只配了 2 核、2GB，而不是宿主机的 96 核、64GB？
- JVM 为什么要在启动最早期就把这些问题搞清楚？

## 2. 一句话顿悟

**平台探测不是“顺手采集环境信息”，而是 JVM 后面几乎所有自适应决策的地基：它必须先搞清楚自己脚下的机器、容器、CPU 和内核边界，后面的 GC、JIT、时间源、堆大小和线程数才不至于全部算错。**

## 4. 重写策略

不改题目，先把单篇写透。

这篇值得独立成篇，因为它对应的是一个真实而高频的困惑：

**JVM 的“自适应”到底建立在什么最初输入之上？**

所以本篇不再写成“探测什么 → 再探测什么”的素材汇编，而要写成：

- 如果 JVM 根本没探测明白自己脚下是什么环境，会先在哪些地方犯大错
- 它为避免这些大错，必须先回答哪几类问题
- 每一类问题分别落到什么探测手段上
- 探测结果又如何进入后面的 GC/JIT/时间/堆/线程这些决策链

## 5. 结构大纲（按理解路径，不按源码顺序）

### 第一节：事故开场——为什么“机器看错了”会直接把 JVM 带沟里

目标：先建立危机感，不先上 `uname/cpuid/cgroup`

要回答：

- 为什么平台探测不是锦上添花，而是生死线
- 容器里把宿主机看成自己，会出什么事
- 把 CPU 能力看错，会出什么事
- 把时钟来源看错，会出什么事

预估字数：900-1200

### 第二节：JVM 启动最早期到底在确认什么

目标：把问题收束成 4 类输入

要回答：

- 我跑在什么系统/内核上
- 我面前这颗 CPU 会什么
- 我到底被分到了多少 CPU
- 我到底能用多少内存

这里先给总图，不急着下源码。

预估字数：700-900

### 第三节：第一类输入——“我跑在谁的地盘上”

目标：讲清楚为什么内核版本、虚拟化类型、时间源策略会捆在一起

子层次：

- 为什么 JVM 不做字符串比较，而是把内核版本压成整数
- 为什么虚拟化探测会影响时间测量与后续采样/JFR
- 这里真正要防的误解是什么：不是“知道机器品牌”，而是“决定后续策略边界”

预估字数：1500-1800

### 第四节：第二类输入——“这颗 CPU 到底能干什么”

目标：讲清楚 CPU 特性位图不是资料表，而是能力开关矩阵

子层次：

- 为什么必须在启动时一次性探测、终身缓存
- 为什么位图而不是逐项函数判断
- 某几位能力如何直接改变 JIT、并发原语、加密路径
- 如果探测错了，最坏会怎样

预估字数：1500-1800

### 第五节：第三类输入——“我以为有 96 核，其实容器只给了 2 核”

目标：把 `processor_count` 与 `active_processor_count` 的区别讲透

子层次：

- 为什么 JVM 需要同时保留“机器有多少核”和“我能用多少核”两个答案
- quota / period / shares 到底谁更可信
- 为什么 GC/JIT/采样线程数依赖后者，而不是前者
- NUMA 为什么也属于“平台探测”的延长线

预估字数：1800-2200

### 第六节：第四类输入——“我到底能吃多少内存”

目标：把 cgroup memory limit 与堆自适应联系起来

子层次：

- 不读容器限额会造成什么真实事故
- 为什么这里必须做 v1 / v2 差异封装
- 为什么 `cpu.shares == 1024` 要被当成“没设”
- 为什么这些指标不能每次现读，而要做 20ms 缓存

预估字数：1800-2200

### 第七节：收网——平台探测为什么是后面整卷的地基

目标：把前文四类输入收束为“后续所有决策的初始条件”

要明确点名：

- GC 线程数
- 编译线程数
- 堆大小
- 时间源/JFR 时间轴
- NUMA 布局与后续内存分配

最后要把下篇虚拟内存自然钩出来：

- 这篇解决“看清脚下”
- 下篇解决“开始向 OS 要内存”

预估字数：700-1000

## 6. 失败方案推演（写正文时必须展开）

至少要展开以下失败方案：

1. JVM 如果完全不看容器，只看宿主机
2. JVM 如果每次都现读 cgroup 文件
3. JVM 如果不缓存 CPU 能力，而是到处临时判断
4. JVM 如果把内核版本一直当字符串处理

## 7. 本篇必须明确澄清的误解

1. 平台探测不是为了打印环境信息，而是为了给后续决策提供输入
2. `processor_count` 和 `active_processor_count` 不是重复字段
3. 容器 CPU 份额不等于真实可用核数，quota 与 shares 的可信度不同
4. 虚拟化探测不只是“知道跑在 KVM 上”，而是影响时钟与测量策略
5. cgroup 指标读取不是越实时越好，过度读取本身会成为开销
