# 00 · 烂大街问题，专家级答案：方法论与规划

## 定位

这个专题回答的是**所有 JVM 面试都会出现的基础题**——“内存分几块”“GC Roots 有哪些”“双亲委派是什么”“JVM 有哪些垃圾回收器”这一类。

题目是烂大街的，但答案标准必须是**技术专家级**：不是背结论，而是能讲清**它为什么成立、在进程里长什么样、在 HotSpot 里谁实现、换版本后哪里会变、最容易答错的坑在哪**。

换句话说，这个专题不是“用源码来出题”，而是**拿最常见的面试题，给出能让面试官明显感受到候选人比普通八股高一个层级的回答**。

## 与 01-18 的区别

- `01-18`：题目本身围绕 HotSpot 源码机制设计，默认候选人已经愿意进入类、函数、元数据和阶段协议。
- `00`：题目本身是所有人都会问的基础题，但答案深度标准仍然对齐 `01-18`。

所以这里的核心不是“把问题问深”，而是**把答案答深**。

## 为什么要单独做这个专题

如果不单独做，基础题很容易出现两个极端：

1. **八股化**：只会背“堆、栈、方法区、程序计数器、本地方法栈”这类结论；
2. **过度源码化**：一上来就讲 `Metaspace::allocate`、`frame::sender_for_compiled_frame`，却没有先把表层问题答对。

这个专题要解决的，就是在这两者之间建立一套**稳定回答框架**：

- 先把题面答对；
- 再从进程和操作系统视角把概念落地；
- 再从 HotSpot 视角把机制钉住；
- 最后用版本差异、边界条件和常见误答把答案拉到专家级。

## 回答的标准框架：四层视角 + 一个收束句

每道题的专家级答案必须包含以下 5 个部分。不是每题都要一样长，但结构必须一致。

### 1. 标准答案（先把题面答对）

先用 2–3 句话把表层答案说对。这一层是任何候选人都应该能给出的及格线。

例如：

- “JVM 规范里有程序计数器、虚拟机栈、本地方法栈、堆、方法区。”
- “volatile 解决的是可见性和禁止重排，不保证复合操作原子性。”
- “双亲委派先让父加载器尝试加载，只有父失败才由子自己定义。”

这层不能错，也不能省略。因为如果连题面都答偏，后面所有“深入”都是在歪楼。

### 2. 进程 / OS 视角（把概念映射到真实机器）

这是拉开差距的一层。把逻辑概念翻译成进程地址空间和 OS 事实：

- 内存区域 → `mmap` 的哪些段、pthread 栈、`dlopen` 加载的 `libjvm.so` 的哪些段
- 线程栈 → 内核线程栈与 JVM 栈守卫页（red/yellow/reserved）
- 方法区 → native memory 中的 Metaspace 虚拟空间
- GC Roots → 实际是谁持有引用、何时被冻结
- JFR/PerfData/NMT → 是共享布局、事件流还是 stop-the-world 快照协议

这层回答直接暴露候选人是不是只背了逻辑定义，还是知道 JVM 真正跑在一个 Linux 进程里。

### 3. HotSpot 实现视角（落到源码/机制）

给出这道结论在 HotSpot 源码里的具体落点：类名、函数名、关键调用链、`file:line`。不要求背源码，但要能指到。比如：

- “方法区搬出堆” → `Metaspace::allocate()` 失败 → `satisfy_failed_metadata_allocation()` → `_metadata_GC_threshold`
- “栈帧大小编译期算好” → `_cb->frame_size()` + `sender_for_compiled_frame`
- “隐式 NPE 是 SIGSEGV 转换来的” → `continuation_for_implicit_exception()` → `ImplicitExceptionTable`

注意：这里不是让候选人一上来背源码，而是让他能证明自己知道**这个结论不是拍脑袋的**。

### 4. 演进边界（版本差异 / 常见误答 / 边界条件）

这层是专家级回答最容易拉开差距的地方。至少要补一个：

- JDK 8/11/17/21 的差异
- 常见误答为什么错
- 哪个边界条件会让这个答案不成立
- 哪个 GC/平台/构建下行为会变化

例如：

- “方法区在堆里”在 JDK 8 之后就过时了；
- “偏向锁在 JDK 17 彻底移除”是错的，JDK 15 默认禁用，JDK 18 才彻底移除实现；
- “PhantomReference 在对象死后通知”不够精确，必须补上“在 Finalizer 复活阶段之后”。

### 5. 收束句（一句把问题提升一层）

最后要有一句让面试官意识到你不是在背定义，而是在理解机制的问题。例如：

- “这题本质上问的不是‘内存放哪’，而是谁拥有这块内存、谁负责证明它该回收。”
- “这题本质上不是问‘GC 有几种’，而是问你把复杂性放在停顿、并发还是屏障哪一边。”
- “这题真正考的是‘你能不能把规范五区映射到一个真实进程的地址空间里’。”

## 明确禁止：这几种回答都算敷衍

### 1. 只列名词，不讲因果

例如：

- “堆、栈、方法区、程序计数器、本地方法栈”
- “Serial、Parallel、CMS、G1、ZGC”
- “双亲委派就是先问父，再问父的父”

这类答案如果没有进一步展开为什么、怎么实现、什么版本变了，都不合格。

### 2. 只背定义，不落进进程世界

例如：

- “方法区放类元数据”但不说 JDK 8 之后是 Metaspace native memory；
- “线程是轻量级进程”但不说 HotSpot 线程最终是 pthread；
- “PerfData 是共享内存”但不说读方为什么可以 `mmap` 而不打扰目标进程。

### 3. 只会从一个视角回答

比如 JVM 内存区域只从规范视角回答，不提进程地址空间；或者只从 HotSpot 视角回答，不先把题面答对。**真正好的答案一定是多层视角叠加。**

### 4. 用“过时版本答案”冒充通用事实

凡是涉及 PermGen、偏向锁、CMS 默认行为、`--illegal-access`、JFR 可用性、G1 默认值，都要补版本边界。

## 广度控制：域 → 基础题映射

为保证不遗漏（比如 attach、PerfData、NMT、JFR），强约束：**每个子目录的题目清单必须能覆盖 `vol-02` 的一个完整域集合**。规划阶段先列出“本题覆盖哪些域”，写成映射，避免只挑热门题。

此外，再加一条广度校验规则：

- 每个子目录至少有 1 道 **规范层问题**
- 至少有 1 道 **进程/OS 视角问题**
- 至少有 1 道 **HotSpot 实现问题**
- 至少有 1 道 **版本差异问题**
- 至少有 1 道 **最常见误答纠偏题**
