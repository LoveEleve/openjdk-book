## 叙事计划

**开篇场景**：JDK 9 开始 G1 是默认 GC。和之前的 CMS/Parallel 完全不同——它不是分代式（固定大小的 Young/Old 区），而是把整个堆切成等大小的 Region（默认 2048 个，每个 1-32MB），Eden/Survivor/Old/Humongous 四种角色动态分配。回收时不是扫整个 Old——是挑垃圾最多的几个 Region（Garbage-First）。

**第一层：Region 模型——堆的积木**

`HeapRegion`（`heapRegion.hpp:191`）大小由 `G1HeapRegionSize` 决定（1-32MB，2 的幂）。四种角色通过 `_type` 标记：`Eden`（分配新对象）、`Survivor`（Eden 存活对象）、`Old`（长期存活对象）、`Humongous`（对象大小 > Region 一半——跨多个 Region）。Region 的边界是逻辑的——`commit`/`uncommit` 物理内存可以动态回收 Region 占用的物理页。

**第二层：GC 周期——Young → Mixed → Young**

G1 周期分三个阶段：`young-only`（Eden + Survivor 回收——Stop-The-World，快）、`concurrent marking`（标记 Old 区域存活对象——和应用并发）、`mixed`（回收部分 Old Region——STW，每次回收一定数量的 Old Region，在 `MaxGCPauseMillis` 预算内尽量多做）。

`G1Policy`（`g1Policy.hpp`）控制周期切换——根据历史 pause 时间和回收效率预测"哪些 Old Region 最值得收"。

**第三层：并发标记——SATB 屏障**

`G1ConcurrentMark`（`g1ConcurrentMark.hpp`）实现 Snapshot-At-The-Beginning 算法。初始标记（`initial-mark`）在 young GC 末尾 piggyback——不增加额外 pause。并发标记阶段多线程扫描对象图，`SATB` 写屏障记录标记开始后所有被修改的引用——保证标记不会漏掉"标记过程中新出现的引用"。

最终标记（`remark`）STW 短暂暂停——处理 SATB buffer 中残留的引用。清理（`cleanup`）计算每个 Region 的存活对象比例——决定哪些进入 mixed collection set。

**第四层：疏散——把活对象复制到新 Region**

`evacuate_collection_set()`（`:740`）和 young GC 共享同一套疏散引擎。G1 用 `G1ParScanThreadState` 实现并行疏散——多个 GC 线程同时把存活对象从 CSet Region 复制到 Survivor/Old Region。`PLAB`（Promotion Local Allocation Buffer）在这里是关键——每个 GC 线程有自己的 PLAB，无锁 bump pointer。

**第五层：RSet——跨 Region 引用的索引**

每个 Region 有一个 `Remembered Set`（`heapRegionRemSet`，~4100 行核心代码）。记录"老年代 Region 中哪些 card 引用了当前 Region 中的对象"。年轻代回收时不需要扫描整个老年代——只看 RSet 就知道哪些 card 有跨代引用。RSet 有三级存储：`sparse`（散列表）→ `fine`（bitmap per card）→ `coarse`（整个 Region 标记为"可能有引用"）。并发 refinement 线程（`G1ConcurrentRefineThread`）在后台维护 RSet——减少 STW 时的 RSet 更新量。

**第六层：Humongous 对象——特大对象的特殊处理**

Humongous 对象（≥ Region 的 50%）跨多个连续 Region。`StartHumongous` + `ContinuesHumongous` 标记。分配时直接从堆分配（不走 TLAB），young GC 不回收 humongous 区域——但并发标记的 cleanup 阶段可以回收"已死 humongous"（`_humongous_reclaim_candidates`，`g1CollectedHeap.cpp:1448`）。

**设计权衡**

一、Region 模型 vs 分代模型。Region 允许灵活调整 Eden/Old 比例（不需要固定分界线）。代价是 RSet 维护开销大——每个 Region 都需要跨代引用索引。

二、并发标记 vs 全 STW。并发标记不阻塞应用但复杂（SATB 屏障 + 并发 refinement）。Young GC 是纯 STW 但很快（几十毫秒）。

三、Mixed GC vs 全量 Full GC。Mixed 每次只收部分 Old Region——spread pause over multiple cycles。代价是需要精确预测回收效率和时间。
