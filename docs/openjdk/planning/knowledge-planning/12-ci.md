## 03 深度分类

### 🔴 Deep — 核心设计决策 (3 KP)
| KP | 为什么 🔴 |
|----|---------|
| ciObject 镜像体系 | 为什么需要 ciKlass/ciMethod——不在 JIT 编译中使用 InstanceKlass 直接——ci 层提供 compiler-friendly 接口 (is_subtype_of/unique_concrete_method) 和 GC 安全。oop→ciKlass 映射由 ciObjectFactory 持有——GC safepoint 时 ciObject 保持不变 |
| ciTypeFlow — 字节码类型流 | JIT 编译器需要知道每个 bci 的栈+局部变量类型——从 bytecode 推导——处理 branch merge/exception handler/loop。这是 C2 的 IdealGraph 构造的前序 |
| bcEscapeAnalyzer — 逃逸分析 | 对象是否"逃逸"当前方法——决定 C2 能否做 scalar replacement (栈上分配, 消除堆分配)——ConnectionGraph 算法 |

### 🟡 Working — 有设计但非核心 (4 KP)
| KP | 说明 |
|----|------|
| ciEnv — 编译环境 | 入口+工厂+依赖跟踪 |
| ciObjectFactory — 创建者 | oop↔ciObject 双向映射 |
| ciMethodData (profiling data) | MDO 的编译器端读取 |
| ciReplay — 编译重放 | 确定性回放——debug JIT bug |
