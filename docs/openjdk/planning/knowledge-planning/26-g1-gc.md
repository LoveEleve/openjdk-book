## 03 深度分类

### 🔴 Deep — 核心设计决策 (5 KP)
| KP | 为什么 🔴 |
|----|---------|
| Region 模型 + Humongous handling | G1 的核心创新——堆不再分固定 Young/Old Generation——而是 ~2048 个等大 Region(1-32MB), 每 Region 独立標記 Eden/Survivor/Old。Humongous object(>50% Region size)→StartsHumongous+ContinuesHumongous 连续 Region 链。Eden 和 Survivor 在 GC 间动态重指定——不是固定位置 |
| SATB 并发标记 + pre-write barrier | 并发标记不 STW (simultaneous with mutator)—用 Snapshot-At-The-Beginning 保证一致性: pre-write barrier 在修改 oop 前保存旧值到 SATB buffer→标记线程通过 SATB buffer 追踪活对象。remark phase 补充并发标记遗漏 |
| RSet + CardTable 三级 coarsening | 每 Region 有 RSet 存 "谁引用了我": sparse(直接存 card index for small sets)→fine(per-region card bitmap)→coarse("这个 Region 所有 card 都 dirty, 不用细查")。G1ConcurrentRefineThread 批量处理 dirty card→更新 RS→按负载自适应调整线程激活和 refinment rate |
| Mixed GC + 集合选择 | G1 的核心 GC 类型: Young-only(仅收集 young regions), Mixed(收集 young + selected old regions)。G1Policy 根据 predict pause time cost 选择哪些 Old Regions 加入 collection set——确保 pause time < target(-XX:MaxGCPauseMillis=200)。IHOP 控制并发标记启动时机(heap occupancy%) |
| G1BarrierSet pre/post write barrier | G1 的写屏障最重(40-50 cycles): pre-write barrier 保存旧值到 SATB buffer(用于并发标记), post-write barrier 标记 card dirty(用于 RS 更新)。两个 barrier 在 Access API 中全 inline——Assembly/ C1/C2 各有 optimized implementation. CardTableModRefBS 继承 + G1CardTable 扩展 |

### 🟡 Working (3 KP)
| KP | 说明 | 为什么 🟡 |
|----|------|------|
| 分配器 (G1Allocator + G1PLAB + TLAB) | 三层分配——Mutator 用的 Old/Young allocation region, GC 用的 PLAB promotion allocation, TLAB 快速分配 | 基础设施——域25已覆盖TLAB/PLAB, G1版本是 adaptation |
| 并发细化(Mutator→DirtyCard→Refinement) | 并发线程处理 dirty card—用 sample rate 控制 activation | G1 RemSet 的辅助——独立性弱 |
| Full GC (last resort) | Serial/Parallel compaction—当 Evacuation/ Mixed GC 腾不出足够空间时, 全堆 Compact | 最后手段——正常操作中不应该出现——"不要触发Full GC" |
