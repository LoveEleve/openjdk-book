# ch01 面试考点

> 本文是 [ch01 Launcher Chain](README.md) 的面试配套，不索引到书籍目录。

## Q1：`/proc/self/exe` 是什么？为什么不用 `argv[0]`？

`/proc/self/exe` 是 Linux 内核暴露的符号链接——无论进程怎么启动、PATH 怎么设置，它永远指向当前进程可执行文件的真实绝对路径。`argv[0]` 可以被调用者伪造（`exec("./java", "fake_name")`），而 `/proc/self/exe` 不可伪造——`readlink("/proc/self/exe")` 是拿到 java 二进制真实位置的唯一可靠方式。

## Q2：`dlopen` 和编译时链接的区别？

编译时链接（`gcc -lfoo`）：程序启动时 `ld.so` 自动加载 .so，符号在 `main()` 之前解析完成。`dlopen`：代码运行时手动加载 .so，失败时可以自行处理（不会直接 crash），适合可选加载和版本选择的场景。java 启动器用 `dlopen` 的核心原因是 **JRE 位置不在编译期确定**——用户安装到 `/opt/jdk-11` 还是 `/usr/lib/jvm/java-11`，编译时不知道。

## Q3：为什么 `pthread_create` 之后再 `pthread_join`，而不是直接在当前线程调 `JavaMain`？

三个原因：(1) 栈控制——新线程可以设置 `pthread_attr_setstacksize(-Xss)` 和 `pthread_attr_setguardsize(0)`（关掉 pthread 默认 guard，JVM 自己用 StackGuardPages）；(2) 线程身份——新线程是干净的 pthread，JVM 可以把它包装为 `JavaThread`，而原始线程已经绑定了信号处理器和 TLS，不适合当 JavaThread；(3) 进程模型——原始线程通过 `pthread_join` 阻塞等待，Java 线程退出后原始线程收集退出码、清理资源。
