# 02-number-math/01 重写规划

> 状态：重写前计划
> 适用规范：`docs/openjdk/WRITING-GUIDELINES.md`
> 版本边界：JDK 11 `java.base` 包装类实现与 JLS 装箱语义。
> 目标：把“IntegerCache 面试题”重写成一篇解释引用身份、值语义、溢出边界和数字对象化成本的文章。

## 1. 读者困惑

- `Integer a=100; b=100; a==b` 为什么可能为 true，而 200 不一定？
- `==`、`equals`、自动装箱和缓存分别在比较什么？
- 为什么数据库/反序列化得到的 Integer 更容易暴露问题？
- `parseInt` 如何在结果尚未完成时检测溢出？
- Long/Short/Byte/Boolean 是否都有相同缓存规则？

## 2. 一句话顿悟

**包装类把“数值”变成了对象，但对象身份和数值相等是两套语义：装箱可能命中缓存，`==` 比的是引用，`equals` 才比值；缓存只能优化常用常量，不能改变业务比较规则。**

## 3. 旧稿问题

- 旧稿事实点齐全，但按 IntegerCache → equals → parse → 其他包装类平铺，缺少“对象身份误用导致业务 bug”的主线。
- 没有先推演 `==` 看似可用、缓存扩大后仍不可靠、反序列化对象绕过缓存等失败方案。
- `-128..127` 规范保证与实现可配置上限没有充分区分。
- parseInt/toString 算法被放在文章末尾，缺少“包装对象只是入口，数字算法仍有边界”的收束。

## 4. 理解路径

### 第一节：事故开场——缓存让错误比较偶尔通过

- 用 100/200 的 `==` 现象开场。
- 失败方案：看到小数值测试通过就把 `==` 推广到所有 Integer。
- 总图：装箱 → valueOf → cache 命中/新对象 → `==` 身份比较；equals 另走值比较。

### 第二节：IntegerCache——规范下限与实现上限

证据：
- `Integer.valueOf(:1056)`。
- `IntegerCache.low/high/cache(:998-1000)`。
- `VM.getSavedProperty(:1004)` 与 AutoBoxCacheMax。
- 类初始化一次性构建缓存。

必须明确：`-128..127` 是规范最低要求，high 可以由实现/启动配置扩大；不能把所有范围都写成固定事实。

### 第三节：比较语义——为什么 equals 才是业务答案

- `Integer.equals(:1212)` 值比较。
- 自动装箱、显式 new、数据库/反序列化来源可能产生不同对象。
- 失败方案：`==`、手动比较引用、只在缓存范围测试。

### 第四节：包装类背后的数字算法

- `parseInt(:604)` 逐字符、radix、先乘后加、溢出前置检查。
- `toString(:437)` 负数边界、两位查表(:499-500)。
- 失败方案：先计算再检查溢出、对 `MIN_VALUE` 取正。

### 第五节：其他包装类与收网

- Long/Short/Byte/Boolean 缓存对照。
- Number 转换协议。
- 回到对象身份/值语义：集合键、数据库结果、API 参数都使用 equals/基本值语义。
- 钩子到 BigDecimal：浮点数的值表示会成为下一次精确性问题。

## 5. 失败方案清单

1. 用 `==` 比较所有包装类。
2. 因为小整数测试通过，就认为缓存范围固定。
3. 把 `new Integer`/数据库/反序列化对象与 valueOf 对象当成同一身份。
4. parse 后再检查溢出。
5. 对 `Integer.MIN_VALUE` 先取正再格式化。

## 6. 误解清单

1. `IntegerCache` 让所有相同整数都 `==`——错误。
2. `-128..127` 是实现固定上限——错误，这是最低保证，high 可扩展。
3. `equals` 比较引用——错误，它比较 int value。
4. parseInt 溢出会自动抛异常——只有实现主动做边界检查才成立。
5. Long/Boolean 缓存规则与 Integer 完全相同——错误，应逐类看实现。

## 7. 证据清单

- `Integer.java:998-1012`：缓存字段、属性、静态初始化。
- `Integer.java:1056`：valueOf。
- `Integer.java:1212`：equals。
- `Integer.java:604`：parseInt。
- `Integer.java:437/499-500`：toString 与数字查表。
- `Number.java:55`：抽象转换协议。

## 8. 版本与边界

- 基于 JDK 11；IntegerCache high 与 `-XX:AutoBoxCacheMax` 属实现/启动配置细节。
- JLS 装箱缓存最低范围与 JDK 实现扩展分开叙述。
- 包装类具体缓存规则必须逐类核对，不能从 Integer 推导全部包装类。
