# 先读这一篇：怎样阅读这卷 Druid 源码分析

> 本文是卷级导读，回答这卷讲什么、为什么这样排、每篇解决哪个读者问题。

## 这卷不是 Druid 配置手册

这卷真正要建立的是两条相互连接的主线：

1. 一条连接如何被初始化、借出、归还、维护、验证和复用。
2. JDBC 操作如何经过 Filter，进入 SQL 统计、安全检查，并最终通过 Spring Boot 被装配出来。

因此不能把 Druid 简化成“HikariCP 加监控”。HikariCP 是对照背景；Druid 的池本体、Filter 链和 SQL 解析器都需要独立理解。

## 推荐阅读路线

### 第一阶段：先立池本体

1. `D-1`：固定数组、`ReentrantLock`、两个 `Condition`、`init()` 与借出协议。
2. `D-5`：`shrink()` 如何扫描、驱逐、keep-alive 和紧凑化，后台任务如何协作。
3. `D-7`：把验证放回借出、空闲、归还三个风险关口；注意 `testWhileIdle` 的实际源码路径。

### 第二阶段：再看扩展与复用

4. `D-2`：Filter 链如何递归推进、复用并接入连接关闭。
5. `D-8`：PreparedStatement 为什么只能按连接缓存，以及 LRU 如何淘汰。

### 第三阶段：补监控、安全与共同地基

6. `D-3`：StatFilter 如何在执行前后记录统计，并借助参数化合并 SQL。
7. `D-4`：WallFilter 如何把 SQL 转成 AST，再由 Visitor 执行规则检查。
8. `D-6`：Lexer → Parser → AST → Visitor → dialect，解释 D-3/D-4 共用的解析器地基。

### 第四阶段：落到真实装配

9. `D-9`：Boot 自动装配如何绑定属性、创建 `DruidDataSourceWrapper`、触发 `init()`，以及按条件注册 Web 统计组件。

## 为什么 D-7 要在 D-2 之前读

现有物理目录是写作过程形成的顺序，不强行重命名目录。卷级规划把 D-7 归入骨架层，因此推荐阅读将它放在 D-1/D-5 之后、Filter 层之前。这样“池如何借还维护验证”的主干先闭合，再进入 JDBC 扩展面。

## 跨篇桥

- `D-1 → D-5`：池数组和连接状态是维护扫描的对象。
- `D-5 → D-7`：维护与借出路径都可能触发连接有效性判断，但 keep-alive 验证不能等同于 `testWhileIdle`。
- `D-1 → D-2`：连接持有者承载 Filter 链复用。
- `D-2 → D-3/D-4`：StatFilter 和 WallFilter 都是链上的具体扩展。
- `D-3/D-4 → D-6`：参数化与安全检查共同消费 AST/Visitor 能力。
- `D-1 → D-9`：Boot 的 `afterPropertiesSet()` 最终调用池的 `init()`。

## 两个阅读提醒

- 代码锚点用于证明关键机制，不代表只看一行就能理解完整状态机。
- 单篇正文讲主干；更细方言差异、Web 控制台内部数据流和生产实践属于本阶段暂缓边界。
