# InternalEngine 怎么把一条文档写入 Lucene 和 Translog

> 本文基于 ES v8.12.2 当前源码。`vol-elasticsearch` 第四篇，回答 InternalEngine 的 plan-and-execute 写入路径。

## 困惑：写入一条文档，ES 内部怎么决定是"新增"还是"更新"？

`PUT /my_index/_doc/1 {"title":"hello"}` 第一次执行时是新增，第二次执行时是更新。ES 怎么判断是新增还是更新？怎么避免重复操作？

`LiveVersionMap.java:337` `maybePutIndexUnderLock()` 在写入后更新内存版本映射，通过 `internalReaderManager` 的 refresh listener 更新。版本映射是并发写入的关键：`readLock` 允许多个 index 并发，`maybePutIndexUnderLock` 保证版本更新的原子性。

## 失败路径

- 版本冲突（`version_conflict_engine_exception`）：`planIndexingAsPrimary` 检测到版本不匹配，返回 `IndexingStrategy.skipDueToVersionConflict`
- 自动生成的 id 重复（`canOptimizeAddDocument` 返回 false）：退化为完整 update 路径
- Lucene `IndexWriter` 满：`indexIntoLucene` 抛异常，`indexResult` 标记为 FAILURE

## 收网

InternalEngine 的 plan-and-execute 模式：`planIndexingAsPrimary()`（L1314）决定策略 → `indexIntoLucene()`（L1384）执行 Lucene 写入 → `Translog.add()` 写 WAL。`canOptimizeAddDocument()`（L1059）利用 autoGeneratedIdTimestamp 实现 append-only 优化。`LiveVersionMap` 管理内存版本，`readLock` 允许多个 index 并发。
