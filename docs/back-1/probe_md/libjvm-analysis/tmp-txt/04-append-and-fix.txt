1. **Production opener**: "You attach an agent with `-agentlib:jdwp`. App latency spikes 3x — every method runs in interpreter because `NotifyFramePop` pinned it. The `at-breakpoint` flag in JavaThread says 'don't compile me, I'm being debugged.'"

2. **Three entry doors**: normal (fresh method call) / exception (handler dispatch) / return (frame pop + re-enter caller). Show EACH entry path with file:line from templateInterpreter.cpp.

3. **Why 3 entries, not 1**: normal=fast allocation+frame init. exception=no allocation, just dispatch to handler. return=no allocation, pop frame, restore caller's stack. Separating them avoids conditional branches in the hot code.

4. **GDB**: break at each of the 3 entry points, step through frame creation/restoration.

### 02-Template-Interpreter.md — add

1. **Production opener**: "`perf top` shows TemplateInterpreter consuming 45% CPU. No JIT log. Because CICompilerCount=1 and queue backlog."

2. **Why TemplateInterpreter is StackObj**: single-pass generation, allocates in CodeBuffer (CodeCache), destructor hooks for cleanup. All 6 bytecodes generate machine code during startup. Don't duplicate 01/18's struct analysis — reference it.

3. **Bytecode → machine code generation flow**: `generate_normal_entry()` → `dispatch_next()` → `TemplateTable::template_for(opcode)` → `template->_gen()`. Show the GENERATION loop, not the EXECUTION dispatch (that's 01/18).

4. **Why macro-driven** (DEF_ALL_INTERPRETER_TYPES, IRT_ENTRY macros): each bytecode → separate `generate_<bytecode>()` function with type-correct TOS allocation. Without macros: 200+ duplicate function signatures.

5. **GDB**: break at generate_normal_entry(), step through dispatch table creation, verify table entries.

### 03-TOS-State-Machine.md — add

1. **Production opener**: "Method returns int but caller expects float — interpreter crashes with wrong stack format."

2. **10 TOS states**: tos_illegal/tos_byte/tos_short/tos_char/tos_int/tos_long/tos_float/tos_double/tos_oop — each with exact `TosState` enum values.

3. **Why per-TOS not runtime check**: Template::_tos_in/_tos_out pair is compile-time type safety. The template generator picks the right template variant statically — no runtime type tag checking. Compare: runtime check = 3 extra instructions per bytecode × 10^8 bytecodes/sec = massive overhead.

4. **Transition rules**: `iload_0` → pushes int → tos changes from tos_illegal → tos_int. `iadd` → pops int+int → pushes int → stays tos_int. `i2f` → pops int → pushes float → tos changes tos_int → tos_float.

5. **Mermaid**: TOS state transition diagram for a short bytecode sequence (iload_0, iload_1, iadd, istore_2).

6. **GDB**: print Template::_tos_in/tos_out for 5 bytecodes, verify state machine.

### 04-Interpreter-Safepoint.md — add

1. **Production opener**: "GC log shows 'To suppress the safepoint wait, add -XX:+SafepointTimeout'. Stack shows all threads in TemplateInterpreter — because a tight loop `for(;;)` has no safepoint poll."

2. **Where the poll lives**: NOT in every bytecode — only on `goto`/`if*`/`tableswitch`/`lookupswitch`/`return` bytecodes. Show the `testl` instruction injected by TemplateTable::safepoint_poll_at() (don't duplicate 12/02's CPU-level analysis).

3. **Why not every bytecode**: polling page read = cache miss (~200 cycles). 10^8 bytecodes/sec × 200 cycles = 20M cycles/sec wasted on polling alone. Only poll at backward branches (loop back-edges).

4. **`!SafepointSynchronize::is_synchronizing()`**: the fast-path check that skips the safepoint transition when no safepoint is pending.

5. **GDB**: break at safepoint_poll_at(), step through testl, verify SIGSEGV on disarmed page.

### 05-Interpreter-Invoke.md — add

1. **Production opener**: "Reflection-based framework: `Method.invoke()` → methodOop dispatch → 6 layers of indirection → 50x slower than direct call."

2. **invokevirtual resolution chain**: Uninitialized (needs resolution) → `LinkResolver::resolve_invokevirtual()` → Resolved (CP cache update) → cached Method* + entry point.

3. **invokeinterface**: itable search → `InstanceKlass::itable_offset_slow()` (not in 12/02, this is runtime semantic). show the slot-level search.

4. **invokestatic**: simplest — single target, no receiver check. `invokespecial`: direct superclass call, no vtable.

5. **Exception handler dispatch**: `InterpreterRuntime::exception_handler_for_exception()` → `Method::fast_exception_handler_bci_for()` → exception table linear search → found: set bcp=handler_bci, push exception ref → not found: pop frame, re-throw to caller.

6. **GDB**: break at resolve_invokevirtual, step through CP cache update. Break at exception dispatch, step through handler search.

### 06-Counters-Tier.md — add

1. **Production opener**: "`-XX:TieredStopAtLevel=0` makes every method interpreter-only. Production app latency spikes 100x."

2. **InvocationCounter**: `MethodCounters::_invocation_counter` — starts at `InvocationCounter::count_limit`, decremented on each method entry. Hit 0 → method "warm" → `InterpreterRuntime::frequency_counter_overflow()` → `CompileBroker::compile_method()`. Carry = 0 at both TIERED and non-TIERED.

3. **BackEdgeCounter**: `MethodCounters::_backedge_counter` — decremented on loop back-edges. Hit 0 → OSR compilation (compile the loop without waiting for full method). Carry = InvocationCounter threshold.

4. **Why TWO counters**: invocation triggers JIT for the whole method (no wasted work). backedge triggers OSR for hot loops (don't wait 100,000 invocations). Without backedge: single hot method with a cold loop blocks JIT. Without invocation: OSR-compiled loop body doesn't help the rest of the method.

5. **InvocationCounter decay**: `interpreter_invocation_count()` decrements on safepoint — keeps JIT from compiling methods that were hot 10 minutes ago. Decay rate = `InvocationCounter::count_limit / warmup_decay_factor` per safepoint.

6. **JIT transition**: `frequency_counter_overflow()` → `CompileBroker::compile_method()` → method compiled → `Method::set_code(nmethod*)` → next invocation enters compiled code directly.

7. **GDB**: break at frequency_counter_overflow(), print counter values before overflow. Break at CompileBroker::compile_method(), verify nmethod entry point.
