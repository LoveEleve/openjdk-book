## 5. Beginner-friendliness — does a Java engineer who knows 04-interpreter understand 05? (10 pts)

### Hardest concepts to parse (check each in the actual docs):
- **Sea of Nodes** (P01): Is this explained? "Unlike linear IR where instructions are in order, Sea of Nodes has NO order — Nodes float freely, connected only by data + control edges. Think of it as 'all operations exist simultaneouly, constrained only by what they depend on.'" Or does the doc just name-drop "Sea of Nodes" without explanation?
- **Chaitin's algorithm** (P03): The doc says "Live → IFG → Coalesce → Simplify → Select." Does it explain what EACH of these means? Live Range? Interference Graph? Coalesce? Simplify? Or does it assume the reader knows graph theory?
- **Deopt** (P05): Does it explain "why would C2 make an assumption that could be wrong?" The answer: because the assumption is true 99.9% of the time → common case is FAST → rare case goes to interpreter → but the common case is 99.9% of calls. If the doc doesn't explain this tradeoff, the reader thinks deopt is a "bug" instead of a "feature."
- **OopMap** (P06): Does it explain WHY bitmask encoding? Not "it uses bitmask" — "what's the alternative (list) and why is it worse?"
- **Profile Maturity** (P07): Does it explain the warmup problem? "If you measured your customers' behavior by watching the first 10 people enter your store, you'd think everyone wants coffee at 7am. You need to watch until lunchtime to see the real pattern."

## 7. First-principles depth (10 pts)

### Counterfactual check per doc:
- P01: Does it explain WHY Sea of Nodes instead of linear IR? "Graph matching for instruction selection is NP-hard — HotSpot avoids this by using ADL patterns with manual matching."
- P02: Does it explain WHY frequency-weighted inline? "Inline = CodeCache cost (callee size) vs benefit (call overhead × call count). Inline when benefit > cost."
- P03: Does it explain WHY Coalesce before coloring? "Eliminating movs BEFORE physical IFG reduces register pressure → fewer spills."
- P04: Does it explain WHY safepoint-based sweeping? "Concurrent free while threads hold references → ABA problem. Deferred: mark now, free at safepoint."
- P05: Does it explain WHY only at deopt points? "If all PCs had OopMaps: 10% CodeCache overhead. Only at safepoints: 2% overhead. The common case (between safepoints) doesn't need GC roots."
- P06: Does it explain WHY bitmask not list? "Compressed: 10 bytes per safepoint vs 40 bytes. 150MB CodeCache savings."
- P07: Does it explain WHY ci objects are immutable snapshots? "If ciKlass changed mid-compilation: inline decisions based on STALE data → compile final decisions → deopt when they're wrong."

### Scoring:
9-10: 6+ docs have explicit counterfactuals with quantified alternatives
