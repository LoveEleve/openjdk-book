"**-MAX_WBITS vs MAX_WBITS**: zlib's windowBits parameter in inflateInit2. MAX_WBITS (positive 15): expect zlib-wrapped stream with 2-byte header. -MAX_WBITS (negative 15): expect raw DEFLATE with no header. JAR entries use raw DEFLATE → -MAX_WBITS. The negative sign tells zlib 'skip the header check.' Using wrong mode → 'incorrect header check' error → ZipException."

"**Inner CEN parsing**: Standard ZipFile reads CEN by seeking to END header (last 22 bytes of file) → gets CEN offset → reads CEN. For nested JARs, the 'file' is a byte[] in memory (extracted from outer JAR entry). Spring Boot's JarFile reimplements this: parse END from byte buffer → get CEN offset → read CEN entries from byte buffer → build hash table. Same algorithm, different data source."
